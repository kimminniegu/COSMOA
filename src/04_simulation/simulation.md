## 1. 목적과 범위

**AI 제형 모델링 탭은 "개인적인 사전 검토 용도"** 다. 영업 담당자가 연구소 의뢰 전에 **제형 · 용기 적합성 · 컨셉원료**를 가볍게 확인한다.

| 영역 | 하는 일 | 상태 |
|---|---|---|
| 제형 | 4개 성분군 배합 조절 → 예측 점도·예상 질감·상대 유동성·총 배합 비율 | 구현됨 (3·4장) |
| 용기 적합성 | 6종 용기 호환도 점수·판정·진단·대체 권장 용기 | 구현됨 (5장) |
| 바이어 제안 가이드 | R&D 연구소 리포트·바이어 세일즈 피칭 생성·복사 | 구현됨 (6장) |
| 개발요청서 파일 분석 | 바이어 의뢰서 PDF·DOCX를 AI로 읽어 시뮬레이터에 적용 | 구현됨 (7장) |
| **컨셉원료 코멘트 창** | 서술형 작성 + 자주 쓰는 컨셉원료 선택 + 원료 정보·특성·효능 표시 | **구현 예정** (8장) |
| **개발요청서 불러오기·연동** | 저장된 개발요청서를 불러와 시뮬레이션 / 모델링 결과를 개발요청서로 연동 | **구현 예정** (9장) |
| **모델링 내역 기록(DB)** | 프로젝트별 저장본으로 저장·불러오기·최종본 | **구현 예정** (9장) |

- 점수·점도는 **브라우저 계산식**이고, Canvas는 **시연용 표현**이다. 실측 유체 해석·안정성 시험 결과가 아니다. 화면 도움말에도 이렇게 안내한다.
- 처방 확정은 연구소의 몫이다. 모델링의 **배합 조절 수치는 개발요청서에 반영하지 않는다** (FIX).

```
+--------------------------------------------------------------------+-----------------------+
| [샘플 미리보기 카드]                                                | [배합 조절 카드]       |

+--------------------------------------------------------------------+-----------------------+
| [용기 적합성 확인]  용기 드롭다운                     | [바이어 제안 가이드]  [스크립트 복사] |
|  호환도 링(0~100) · 판정 칩 · 패키징 진단             |  R&D 연구소 리포트 / 권장 조치      |

+--------------------------------------------------------------------------------------------+
```

- 밝은 공통 디자인(회색 배경 + 흰 카드)을 따른다. 색상·간격·굵기는 공통 Variable 을 쓴다 ([디자인 시스템](../../docs/design_system.md)).
- **Desktop (폭 1200px 이상 · 높이 700px 이상)**: 화면 높이에 맞춰 스크롤 없이 표시한다 (`height: calc(100dvh - 페이지 상단 여백 - Footer)`, `overflow: clip`).
  - 행 비율: 제목 `auto` / 상단 미리보기·배합 조절 `8fr` / 하단 용기 적합성·제안 가이드 `2fr`. 하단 행은 용기 적합성 카드 내용 높이 아래로 줄지 않는다.
  - 바이어 제안 가이드는 행 높이 계산에서 빠지고(`contain: size`), R&D 리포트와 세일즈 피칭을 2열로 두고 넘치면 카드 안에서 스크롤한다.
- 본문 폭이 좁으면 Container Query 로 1열 배치로 바뀐다.
- 컨셉원료 코멘트 창(8장)과 프로젝트·저장 버튼(9-5)이 추가되면 위 배치를 다시 그린다 (**제안** 9-5).

## 3. 배합 조절과 계산 — 구현됨

### 3-1. 슬라이더 (% w/w)

| 항목 | id | 범위 · 눈금 | 설명 |
|---|---|---|---|
| 유효 활성 성분 | `active` | 0~15 · 0.5 | 제품 목적 성분군 (예: 나이아신아마이드, 아데노신, 펩타이드류) |
| 점증제 (카보머) | `carb` | 0~1 · 0.01 | 점도·겔 구조. 카보머 기준 계산 |
| 유상 오일 성분 | `oil` | 0~45 · 1 | 발림성·유분감 (예: 스쿠알란, 호호바씨오일) |
| 수분 유지 성분 | `hum` | 0~25 · 1 | 보습 (예: 글리세린, 부틸렌글라이콜) |

- 샘플 제형 프리셋: 세럼(2 / 0.20 / 5 / 8, 스포이드), 고농축 앰플(3 / 0.35 / 8 / 10, 스포이드 · 기본값), 로션(1 / 0.45 / 18 / 8, 펌프), 영양 크림(2 / 0.80 / 28 / 10, 크림 자).
- 슬라이더 범위·눈금은 `service.py` 의 `FORMULA_LIMITS` 와 같아야 한다.

### 3-2. 계산식

정제수 자동 계산 (총 배합 비율은 항상 100%):

$$\text{Water}(\%) = \max\left(0,\ 100 - (\text{Active} + \text{Carbomer} + \text{Oil} + \text{Humectant})\right)$$

예측 점도 (cPs):

$$\eta = \text{Round}\left(80 + (\text{Carbomer} \times 10)^{2.3} \times 260 + \text{Oil}^{2} \times 22 + \text{Humectant} \times 18 + \text{Active} \times 45\right)$$

상대 유동성 지수 (0~100):

$$\text{Flow} = \text{Round}\left(\frac{100}{1 + \eta / 6{,}500}\right)$$

### 3-3. 표시 지표

| 지표 | 기준 |
|---|---|
| 예상 질감 | η < 2,500 `묽은 워터리` / < 9,000 `산뜻한 점성` / < 25,000 `농축 리치` / 그 이상 `고밀도 밤(Balm)` |
| 포뮬러 안정성 (참고) | 정제수 < 45% 또는 (오일 ≥ 20% · 점증제 < 0.2%) → `주의` / 정제수 < 60% 또는 (오일 ≥ 12% · 점증제 < 0.2%) → `검토` / 그 외 `안정`. 실제 안정성 시험 결과 아님 |
| 유동 문구 | η < 9,000 `빠른 유동성 · 얇은 퍼짐성` / < 25,000 `완만한 레벨링 · 보습 밀착` / 그 이상 `형태 유지 · 높은 응집력` |

## 4. Canvas 시연 — 구현됨

- 점도의 제곱근 스케일로 퍼짐과 돔 높이를 정한다. 저점도는 돔 없이 넓게 퍼지고, 30,000 cPs 이상은 방울이 팁에 매달려 떨어지지 않는다.
- 착지 반응 (시연용 표현, 실측 유체 해석 아님): 같은 제곱근 스케일에서 에너지(1 − 두께 계수)로 강도를 정한다.
  - 저점도: 착지 직후 수면이 왕관 모양으로 솟고(에너지 > 0.55) 비산 방울(최대 16개)이 날아간다. 웅덩이 안에 떨어지면 작은 파문, 밖에 떨어지면 샬레 바닥에 2.5초간 남는 비드. 파문은 최대 3겹.
  - 중·고점도: 두께 계수 0.6 이상은 튀지 않는다. 0.3 이상은 방울이 수면 위에 쌓였다가 점도에 비례한 시간(약 0.2~2초) 동안 퍼지며 합쳐지고, 파문은 한 겹만 짧게 생긴다.
- [시연 일시정지] 로 멈추고 다시 재생한다. `prefers-reduced-motion` 이면 처음부터 정지 상태다. 탭이 숨겨지면 애니메이션을 멈춘다.

## 5. 용기 적합성 — 구현됨

| 용기 | key | 적합 (cPs) | 주의 (cPs) | 부적합 | 이상 점도 | 주요 결격 사유 |
|---|---|---|---|---|---|---|
| 스포이드 (Dropper Pipette) | `dropper` | 500~5,000 | 100~499 / 5,001~8,500 | < 100 · > 8,500 | 2,500 | 고점도 흡입 불가, 저점도 흘러내림·누수 |
| 원터치 디스펜서 보틀 | `onetouch` | 50~1,500 | 10~49 / 1,501~4,000 | < 10 · > 4,000 | 470 | 고점도 캡 토출 불량 |
| 파인 미스트 스프레이 | `mist` | 1~300 | 301~800 | > 800 | 39 | 분사 입자 불균일·노즐 막힘 |
| 디스펜서 펌프 | `pump` | 800~18,000 | 200~799 / 18,001~28,000 | < 200 · > 28,000 | 5,000 | 고점도 노즐 막힘·복귀 지연, 저점도 비산 |
| 에어리스 펌프 | `airless` | 2,000~60,000 | 500~1,999 / 60,001~80,000 | < 500 · > 80,000 | 15,000 | 초고점도 피스톤 불능 |
| 크림 자 (Cream Jar) | `jar` | 18,000 이상 | 9,000~17,999 | < 9,000 | 45,000 | 저점도 흘러넘침 |

호환도 점수 (0~100, 같은 배합·용기는 항상 같은 점수):

* **적합 (90~100점):** $\text{Score} = 100 - \min\left(10,\ \text{Round}\left(12 \times \left|\log_{10}\frac{\eta}{\text{ideal}}\right|\right)\right)$. 95점 이상은 `최적 적합` 녹색, 90~94점은 `최적 적합` 파란색.
* **주의 (65~75점):** 적합 경계에서 주의 경계까지 벗어난 비율 $t$(0~1)로 $\text{Score} = 75 - \text{Round}(10t)$.
* **부적합 (5~40점):** 주의 경계 대비 배율 $r$(상한 초과 $\eta/\text{high}$, 하한 미만 $\text{low}/\eta$)로 $\text{Score} = \max(5,\ \text{Round}(40 - 9\log_2 r))$.

- 대체 권장 용기: 현재 점도에서 `적합` 인 용기를 버튼으로 보여 준다. 누르면 그 용기로 바뀌고 점수를 0.3초 카운트업한다 (배합은 그대로). 적합 용기가 없으면 "배합과 용기 사양을 함께 조정하세요" 안내.

## 6. 바이어 제안 가이드 — 구현됨

같은 점도·용기·점수로 두 문구를 함께 만든다.

| 구분 | 내용 |
|---|---|
| R&D 연구소 리포트 | `점도 {η} cPs · {용기}: {위험 요약} (호환도 {점수}점).` + 권장 조치 (적합: 현 용기 유지 후 토출량·안정성 시험 권장 / 그 외: 대체 권장 용기로 변경 권장 또는 배합·용기 동시 재검토) |
| 바이어 세일즈 피칭 | 적합: 매칭한 용기로 프리미엄 구성 제안 / 그 외: 대체 용기 적용 제안 또는 배합·전용 용기 동시 조정 제안 |

- [스크립트 복사] 는 두 문구를 `[R&D 연구소 리포트]` · `[바이어 세일즈 피칭]` 제목과 함께 클립보드에 복사한다. 실패하면 버튼 문구로 알린다.
- 컨셉원료 코멘트(8장)가 있으면 가이드에 함께 넣을지는 **미정** (작업 후 결정).

## 7. 개발요청서 파일 분석 (OpenAI) — 구현됨

* **진입:** [개발요청서 분석/적용] → 업로드 모달 (PDF·DOCX, 20MB 이하, 클릭 또는 드래그 앤 드롭).
* **분석:** `POST /api/ai-formulation/brief` (multipart `file`) → `service.py` 가 OpenAI Responses API(`input_file`, Structured Outputs)로 문서를 읽는다.
  * `.env` 의 `OPENAI_API_KEY`, 모델 `SIMULATION_OPENAI_MODEL` (기본 `gpt-4.1`).
  * 원본 파일은 서버에 저장하지 않고 `store: false` 로 요청한다. 문서 안의 지시문은 따르지 않도록 지시한다.
  * 진행 표시는 실제 경과 초를 보여 주고, 모달을 닫으면 요청을 취소한다.
  * 실패(키 없음·한도 초과·파일 거부 등) 시 업로드 화면으로 돌아가 오류 문구를 보여 주고, 임의 값으로 대체하지 않는다.
* **AI 가 추출하는 값:** 문서 코드, 제품명, 제형 종류, 질감, 목표 점도(숫자가 있을 때만 · 근거 문장/페이지), 4개 성분군 배합 추정치(서버에서 슬라이더 범위·눈금으로 보정), 요청 용기(6종 중 하나 또는 없음), 유효성분·함량, 근거 인용문(최대 6개), 요약, 배합 추정 근거.
* **브라우저 계산 (AI 가 점수를 만들지 않음):** 점도는 문서에 명시되면 그 값, 없으면 추정 배합으로 3-2 식. 용기는 문서에 명시되면 그 용기, 없으면 5장 점수가 가장 높은 용기.
* **결과 확인 단계:** 적용 전에 추출값과 `의뢰서 명시` / `AI 추정` 배지, 문서 근거 인용문(페이지)을 보여 주고 [시뮬레이터에 적용] 또는 [다른 파일 올리기] 를 고른다.
* **적용 시:** `{문서 코드} 의뢰서 스펙 동기화됨` 토스트, 슬라이더·지표·점수가 0.5초 롤링 전환, 샘플 제형 드롭다운에 `개발요청서 · {문서 코드}` 선택 및 `스펙 반영됨` 배지.
* **수동 조정:** 슬라이더를 움직이면 배지가 `기준 · 수동 조정` 으로 바뀌고 3-2 계산식 점도로 전환된다. 드롭다운에서 개발요청서 항목을 다시 고르면 분석값으로 돌아간다.
* 이 기능은 **바이어 원본 파일**을 읽는 경로다. 팀이 저장한 개발요청서는 9-3 의 **저장본 불러오기**로 읽는다 (PDF 재업로드를 기본 경로로 삼지 않음 — 개발 안내 1-3).

## 8. 컨셉원료 코멘트 창 — 구현 예정

### 8-1. 요구사항 (확정(FIX))

1. **서술형 코멘트**를 자유롭게 작성한다.
2. **자주 쓰는 컨셉원료 예시**를 클릭(또는 드롭다운 선택)하면 바로 적용된다.
3. 적용한 원료의 **정보 · 특성 · 효능**을 함께 보여 준다.

### 8-2. 구현 방안 — 미정 (직접 작업해 본 뒤 하나를 선택)

| | 방안 1 — 원료명 확인 후 AI 검색 | 방안 2 — 키워드로 AI 추천 |
|---|---|---|
| 흐름 | 주력(자주 쓰는) 컨셉원료 드롭다운에서 원료명 확인 → 모델링 탭 하단 **AI 검색창**에 원료명 입력 → OpenAI API 가 해당 원료의 정보·특성·효능을 **요약**해 표시 | 모델링 탭 하단 **AI 검색창**에 원료명 **또는 원하는 기능 단어**(예: 미백, 탄력, 재생) 입력 → AI 가 키워드에 맞는 **컨셉원료를 추천** + 각 원료의 정보·특성·효능 요약 표시 |
| 장점 | 원료를 정확히 알고 있을 때 빠름, 결과가 한 원료로 좁혀짐 | 원료를 모를 때 탐색 가능, 바이어 요구(기능) 중심 |
| 확인할 점 | 드롭다운 목록 관리 | 추천 개수·근거 표시, 결과 일관성 |

- 두 방안 모두 결과는 "코멘트에 추가" 버튼으로 코멘트 목록에 넣는다.
- 자주 쓰는 컨셉원료 목록 후보 (**미정**, 작업 중 확정): 나이아신아마이드, 아데노신, 레티놀, 아스코빅애시드(비타민 C), 히알루론산, 세라마이드, 펩타이드, 병풀추출물(시카), PDRN, 판테놀. 목록은 이 폴더 안에 한 곳에서 정의한다.

### 8-3. 공통 규칙 (두 방안 공통)

- AI 요약은 **참고 정보**로 표시한다 ("AI 요약 · 확인 필요"). 함량·규제 판단을 단정하지 않으며, 규제 확인은 인허가 규제 탭을 안내한다.
- AI 응답은 정해진 형식(원료명, 정보, 특성, 효능 태그, 주의점)으로만 받고 화면에는 `textContent` 로만 넣는다.
- 실패 시 오류 문구를 보여 주고 임의 값으로 채우지 않는다. 키·모델은 기존과 같은 `OPENAI_API_KEY`·`SIMULATION_OPENAI_MODEL` 을 쓴다.
- 실제 AI 호출은 비용이 발생하므로 입력 후 버튼(또는 Enter)으로만 요청한다 (자동 완성 호출 없음).
- 코멘트 한 항목 구조 (제안): `{ name, comment, info: { summary, properties, efficacy_tags[], caution }, source }` — `source` ∈ `preset`(예시 선택) / `ai_search`(방안 1) / `ai_recommend`(방안 2) / `manual`(직접 입력). 효능 태그는 개발요청서 `ingredients.concept[].efficacy_tags` 와 같은 자유 입력 문자열로 맞춘다.
- AI 호출에는 새 서버 경로가 필요하다 → 9-6.

## 9. 프로젝트 연결 및 저장·불러오기 계획 — 제안 (팀 합의 후 확정)

> 공통 저장 API·고객사·프로젝트 API 는 이미 구현되어 있다 ([API 계약](../../docs/api_contract.md) 2·5장). 이 장은 모델링 탭이 그것을 어떻게 쓸지에 대한 **담당자 제안**이다.
> **공통 버튼(프로젝트 선택·저장·불러오기·최종본) 위치는 각 탭 담당자가 제안한 뒤 함께 합의한다.** 확정한 내용은 공통 문서([공통 UI 규격](../../docs/ui_components.md))에 반영한다 (개발 안내 9-1).

### 9-1. 프로젝트 연결

| 시점 | 처리 |
|---|---|
| 페이지 진입 | 프로젝트 없이도 바로 시뮬레이션할 수 있다 (개인 사전 검토 용도). 상단에 "프로젝트를 선택하지 않았어요" 표시 |
| 프로젝트 선택 | 고객사 → 프로젝트 순으로 선택 (없으면 새로 만들기). 개발요청서 탭과 같은 동작 |
| 작업 시작 | **처음 저장하거나 개발요청서를 불러올 때** 그때 선택된 프로젝트가 이 모델링 작업의 **연결 프로젝트**가 된다. 저장은 항상 연결 프로젝트(id)로 한다 — 화면에서 지금 고른 프로젝트와 혼동하지 않는다 |
| 프로젝트 없이 작업 중 선택 | "이 프로젝트에 연결할까요?" 확인 후 **현재 배합·코멘트를 유지한 채** 연결 |
| 연결된 작업 중 다른 프로젝트 선택 | **먼저 확인**을 묻는다. 취소 → 선택을 되돌리고 그대로 유지. 확인 → 배합·코멘트·불러온 요청서를 초기화(기본 프리셋)한 뒤 바꾼다 |
| 프로젝트 없이 [저장] | 저장하지 않고 프로젝트 선택을 먼저 안내한다 |
| 새로 고침 | 선택한 프로젝트는 브라우저 탭 단위(`sessionStorage`)로 기억하고 서버에서 다시 확인한다 (없어졌거나 보관됐으면 해제). 저장하지 않은 배합·코멘트는 사라진다 |

### 9-2. 저장 데이터 — `tab = simulation`, `schema_version = 1` (제안)

저장은 항상 **새 버전 추가**다. 버전 번호·작성자는 서버가 정한다. `title` 은 저장본 이름 (기본값: `{개발요청서 제목 또는 제품명} 모델링`, 사용자가 수정 가능).

| 칸 | 키 | 필수 | 내용 · 예시 |
|---|---|---|---|
| `context` | `customer_id`, `customer_name`, `project_id`, `project_name` | ✓ | 연결 프로젝트 (이름은 저장 당시 사본) |
| | `source_requisition` | | 불러온 개발요청서 저장본 `{ version_id, version_no, title }`. 없으면 `null` — **FIX "개발요청서 번호(제목)"** |
| | `brief_file_name` | | 7장 파일 분석을 썼다면 파일명만 (`"buyer_brief.pdf"`). 없으면 `""` |
| | `creation_method` | ✓ | `manual`(직접) / `brief_upload`(파일 분석) / `requisition_load`(저장본 불러오기) |
| `inputs` | `preset` | ✓ | `serum` · `ampoule` · `lotion` · `cream` · `brief` |
| | `formula` | ✓ | **배합 조절 항목과 수치** `{ active: 3.0, carbomer: 0.35, oil: 8, humectant: 10 }` |
| | `package` | ✓ | 선택한 용기 key (`dropper` 등) |
| | `concept_comments` | | 컨셉원료 코멘트 목록 (8-3 구조). 없으면 `[]` |
| | `comment` | | 전체 서술형 코멘트. 없으면 `""` |
| `outputs` | `predicted_viscosity_cps`, `viscosity_basis` | ✓ | **예측 점도** `12450`, 기준 `formula`(계산식) / `stated`(의뢰서 명시) |
| | `total_ratio` | ✓ | **총 배합 비율** `{ active, carbomer, oil, humectant, water, total: 100 }` |
| | `texture`, `flow_index`, `stability` | ✓ | **예상 질감** `"농축 리치"`, **상대 유동성** `34`, 포뮬러 안정성 `stable` |
| | `package_fit` | ✓ | **용기 적합성** `{ package, state, score, label, diagnosis }` |
| | `recommended_packages` | ✓ | **대체 권장 용기** key 목록 `["airless", "pump"]` |
| | `buyer_guide` | ✓ | **바이어 제안 가이드** `{ rd_report, rd_action, sales_pitch }` |
| `meta` | `brief_evidence` | | 파일 분석 근거 인용문 (최대 6개, 짧은 발췌만) |
| | `calc_version` | ✓ | 계산식 버전 (`"sim-calc-1"`) — 계산식이 바뀌어도 저장 당시 결과를 구분 |

**저장하지 않는 내용**: 업로드한 원본 파일·파일 본문(base64), OpenAI 원본 응답 전체, Canvas·애니메이션 상태, 도움말·모달 열림 등 화면 상태, 작성자 정보(서버가 기록), 버전 번호.

### 9-3. 불러오기

**(1) 모델링 저장본 불러오기** — 같은 프로젝트의 모델링 저장본 목록(최신순, 최종본 ★ 표시)에서 고른다.
- 복원: 샘플 제형, 슬라이더 4개, 용기, 컨셉원료 코멘트, 전체 코멘트, 불러온 개발요청서 표시.
- 지표·점수·가이드는 **저장된 `inputs` 로 다시 계산**해 표시한다. 저장 당시 `outputs` 와 다르면(계산식 변경 등) "저장 당시 결과와 달라요" 안내 후 저장값을 함께 보여 준다.
- 파일 분석으로 만든 저장본이어도 원본 파일은 복원되지 않는다고 안내한다.
- 불러온 저장본을 고쳐 저장하면 `based_on_id` = 불러온 저장본.

**(2) 개발요청서 불러오기** — 기존 개발요청서를 모델링 탭으로 다시 불러와 제형과 용기 적합성을 즉시 시뮬레이션·검증한다 (FIX). 저장된 요청서 **payload** 를 읽으며, PDF 를 다시 올리지 않는다.
- 같은 프로젝트의 개발요청서 저장본 목록에서 고른다. **개발요청서 최종본이 기본 선택**이다 (FIX).
- 요청서 → 모델링 반영 (제안):

| 개발요청서 v1 키 | 모델링에서 쓰는 곳 |
|---|---|
| `inputs.product_name`, 저장본 `title`·`version_no` | 불러온 요청서 표시, `context.source_requisition` |
| `inputs.product_type_detail` (세럼·앰플·로션·크림 …) | 샘플 제형 프리셋 선택 (해당 없으면 현재 배합 유지) |
| `inputs.product_development.texture` · `viscosity` | 목표 질감·점도 서술 표시. 숫자(cPs)가 적혀 있으면 목표 점도로 사용 |
| `inputs.product_development.container_reference` | 요청 용기 (스포이드·에어리스·펌프·자·미스트·원터치 단어로 6종 매칭, 없으면 점도 기준 최적 용기) |
| `inputs.ingredients.concept[]` (`name`·`kind`·`efficacy_tags`) | 컨셉원료 코멘트 목록에 미리 채움 (`source: requisition`) |

- 배합 수치는 요청서에 없으므로 프리셋 기본값에서 시작하고 사용자가 조정한다. 요청서 서술만으로 배합을 AI 로 추정할지는 **미정**.

### 9-4. 최종본

- 최종본 지정 대상: **모델링 저장본 1개** (프로젝트별). 지정·변경·해제는 공통 최종본 API 를 쓰며, 다른 사람이 먼저 바꿨으면(409) 편집 내용을 유지하고 바뀐 상태만 보여 준다.
- 다른 탭에서 쓰는 내용: 개발요청서 탭이 모델링 저장본을 불러올 때 **최종본이 기본 선택**된다. 반영 허용 범위 (FIX):

| 모델링 값 | 개발요청서 반영 위치 |
|---|---|
| 예상 질감 · 예측 점도 | 02 제품 개발 요구사항 · 텍스처(`texture`) · 점도(`viscosity`) 칸 |
| 컨셉원료 코멘트 | 03 원료 요구사항 · 컨셉 원료 (`ingredients.concept`) |
| 용기 적합성 · 대체 권장 용기 (참고값) | 02 · 용기 (참고값) (`container_reference`) |
| **배합 조절 수치** | **반영하지 않음** |

- 반영 기록(`version_links`)은 개발요청서 쪽이 새 버전을 저장할 때 함께 남긴다. 모델링 저장본이 나중에 바뀌어도 이미 저장된 요청서는 그대로다.
- 최종본 지정은 발송 사실이 아니다.

- 공통 UI 가 합의되면 그 배치를 따른다.
