## 1. 화면 개요

로그인 후 처음 보이는 화면이다. 해외영업 담당자가 **화장품 업계 최신 뉴스**를 중심으로, 환율과 수출 흐름, **바이어 현지 시각**, **해외 규제 업데이트**를 **스크롤 없이 한 화면에서** 확인한다.

아래 표는 **실제 구현된 배치(v0.6)** 기준이다.

| 구역 | 비중 | 내용 | 데이터 |
|---|---|---|---|
| 사이드바 | 고정 | 로고, 메뉴, 사용자 정보(이름 첫 글자 아바타·이름·소속), 로그아웃 | 세션 (`current_user`) |
| 인사말 줄 | 작게 | 날짜 · [이름]님, 시간대별 인사말 | 서버(KST) |
| 상단 줄 왼쪽: 환율 띠 | 가로 약 2/3 | 통화 6개의 매매기준율과 전일 대비 등락 | 한국수출입은행 API |
| 상단 줄 오른쪽: 바이어 현지 시각 | 가로 약 1/3 | 수출 상위국 4곳 또는 직접 선택한 도시의 현재 시각·업무 상태 | 관세청 API(순위) + 브라우저 계산(시각) |
| 왼쪽 열: 화장품 수출입 | 폭 약 40% | 카드 3개 — 월별 수출입 요약(12개월 막대), 수출 상위국, 품목별 수출(HS 6단위) | 관세청 API + pandas 정리 |
| 오른쪽 열 위: 화장품 최신 뉴스 | 폭 약 60%, 높이 절반 이상 | 전문지 5곳 + 식약처 기사를 하나의 목록으로 통합, 검색창 | 장업신문, CMN, 뷰티누리, 코스인코리아닷컴, 코스모닝, 식약처 |
| 오른쪽 열 아래: 규제 업데이트 | 나머지 높이 | 해외 화장품 규제 관련 최신 소식, 실시간 표시 | KOTRA 단신속보뉴스 API, 구글 뉴스 RSS |

로그인 화면은 12장에 따로 적는다.

UN Comtrade 세계 수입시장 탭은 시험 후 제외(연간 자료·외부 키 의존). 알림 버튼은 미구현 |

### 2-1. 크기 배분 (1440 × 900 기준)

| 구역 | 크기 | 비고 |
|---|---|---|
| 인사말 줄 | 한 줄 | 날짜와 인사말 |
| 상단 줄 (환율 띠 + 현지 시각) | 높이 약 110px | 환율 2/3, 현지 시각 1/3, 같은 높이 |
| 아래 영역 | 나머지 높이 전부 | 왼쪽·오른쪽 두 열, 높이 동일 |
| 왼쪽 열 (수출입 카드 3개) | 폭 약 40% | 위: 월별 요약(막대 그래프), 가운데: 수출 상위국, 아래: 품목별 수출 |
| 오른쪽 열 | 폭 약 60% | 위: 뉴스, 아래: 규제. 목록은 남는 높이만큼만 표시 (`data-fit`) |

| 작은 화면 | 높이 820px 이하 또는 폭 1024px 이하 | 한 화면 규칙을 풀고 페이지 스크롤 허용 |

### 2-3-1. 왼쪽 열: 화장품 수출입 카드 3종

v0.5의 "수출 요약 카드 1개"를 왼쪽 열 카드 3개로 늘렸다. 데이터는 관세청 수출입실적을 `home_trade.py`(pandas)로 정리해 만든다.

| 카드 | 내용 |
|---|---|
| 화장품 수출입 · [최근 월] | 왼쪽: 수출·수입·무역수지 3줄(라벨 · 값 · 전년 동월 대비 `kpi-delta`)과 회색 패널의 12개월 수출 누계. 오른쪽: 회색 패널 안 "월별 수출액" 꺾은선(공통 차트: 세로축 눈금값·단위, 격자, 마지막 값, 점 툴팁). 1400px 이하에서는 값 글자를 줄여 한 줄 유지 |
| 수출 상위국 · 최근 12개월 | 수출액 상위 3개국과 금액, 비중 |
| 품목별 수출 · HS 6단위 · 최근 12개월 | 수출액 상위 3개 품목(HS 6단위 코드 + 우리말 품목명)과 금액 |

세 카드 모두 데이터가 없으면 "불러오는 중이에요" 또는 실패 안내만 표시하고 나머지 화면은 그대로 나온다. 수집 방법은 5-7, 결측치 처리는 5-8. 카드를 누르면 품목·기간·국가·지표를 고를 수 있는 **상세 모달**이 열린다 (5-9).

### 2-4. 오른쪽 위: 화장품 최신 뉴스

| 요소 | 내용 |
|---|---|
| 제목 줄 | 화장품 최신 뉴스 + 작은 검색창(`/news?q=`로 이동) + 마지막 업데이트 시각 + 더보기 |
| 기사 목록 | 전체 출처 기사를 합쳐 최신순, **1열 약 7~8건** (화면 높이에 맞춤) |
| 기사 한 칸 | 출처 뱃지(장업신문 / CMN / 뷰티누리 / 코스인 / 코스모닝 / 식약처), 기사 제목(최대 2줄, 넘치면 …), 게시 시간 |
| 공식 발표 표시 | 식약처 보도자료는 뱃지 색을 달리해 공식 발표임을 구분 |
| 클릭 | 원문 기사 페이지를 새 탭으로 열기 |
| 뉴스 더보기 | 제목 줄 오른쪽. `/news` 전체 목록 페이지로 이동 — 검색어(q)·매체(source) 필터, 검색어 강조, 검색 시 구글 뉴스 웹 검색 결과("웹 검색" 출처)도 함께 표시. 페이지 스크롤 허용 |
| 탭 | 없음 (팀 의견에 따라 매체 통합) |

기사 본문, 요약문, 사진은 표시하지 않는다 (6-5 참고).

### 2-5. 상단 줄 오른쪽: 바이어 현지 시각

| 요소 | 내용 |
|---|---|
| 제목 | 바이어 현지 시각 |
| 보기 전환 | 카드 오른쪽 위 탭: **수출 상위국** (기본) / **내가 선택**. 선택 모드에서만 "편집" 버튼 표시 |
| 수출 상위국 | 한국 화장품 수출액 상위 4개국의 시각을 자동 표시 (관세청 데이터 기준, 7-2 참고) |

| 업무 상태 | 업무 중(현지 평일 09~18시) / 업무 외 / 주말 |

### 2-7. 한 화면 유지 규칙

| 규칙 | 내용 |
|---|---|
| 페이지 높이 | `height: 100vh`, 본문 `overflow: hidden` |
| 아래 영역 | 남은 높이를 모두 차지 (`flex: 1`), 왼쪽·오른쪽 열 높이 동일 |
| 목록 개수 조정 | 뉴스·규제 목록 모두, 영역 높이 ÷ 한 칸 높이만큼만 표시. 목록 안 스크롤 없음 |
| 제목 넘침 | 2줄에서 자르고 … 표시 (`-webkit-line-clamp: 2`) |
| 좁은 화면 | 폭 1024px 이하면 두 열을 세로로 쌓고, 높이 820px 이하면 페이지 스크롤 허용 (한 화면 규칙은 데스크톱 기준) |

## 5. 화장품 수출입 요약 기능

### 5-1. 데이터 출처 결정

| 방법 | 문제점 / 장점 | 결정 |
|---|---|---|
| K-stat에 팀 계정으로 자동 로그인해 크롤링 | 공개 API 없음. 계정 비밀번호를 서버에 저장해야 함. 회원용 데이터 재표시는 이용약관 위반 소지. 로그인 방식이 바뀌면 중단 | 자동 수집에는 쓰지 않음 |
| 관세청_품목별 국가별 수출입실적(GW) API | 공공데이터포털 무료 REST API. HS 코드별 수출·수입 금액, 무역수지 제공 | **사용** |

국내 수출입 통계는 K-stat도 관세청 통관 자료를 바탕으로 하므로 같은 원천의 숫자다. K-stat은 개발 중 **수치 검증용**으로 쓰고, 카드에 **링크**로 연결해 사용자가 직접 상세 조회하게 한다.

### 5-2. API 정보

| 항목 | 내용 |
|---|---|
| 이름 | 관세청_품목별 국가별 수출입실적(GW) |
| 신청 | 공공데이터포털(data.go.kr) 활용신청 → 개발계정 자동 승인 |
| 형식 | REST, XML 응답 |
| 트래픽 | 개발계정 하루 10,000건 |
| 사용 값 | `hsCd`(HS 코드), `expDlr`(수출금액, 달러), `impDlr`(수입금액, 달러), `balPayments`(무역수지, 달러) |
| 인증키 보관 | `.env`의 `DATA_GO_KR_KEY` (`.env.example`에는 이름만) |

요청 주소와 요청 변수(조회 기간, HS 코드 등)의 정확한 이름은 공공데이터포털에서 받는 기술문서로 확인한다.

### 5-3. 화장품 HS 코드

| HS 코드 | 품목 |
|---|---|
| 3303 | 향수, 화장수 |
| 3304 | 미용·메이크업·기초화장품 (선크림, 매니큐어 포함) |
| 3305 | 두발용 제품 |
| 3307 | 면도용, 탈취제, 입욕제 등 |

기본값은 **3304** 하나이며 `.env`의 `COSMETIC_HS_CODES`(쉼표 구분)로 바꿀 수 있다. 3303·3304·3305·3307까지 합칠지는 팀에서 정한다 (3306 치약·구강용품은 제외). 구현에서는 응답을 **HS 6단위**(`hsCd`)로 저장해 품목별 카드에 쓴다 (`home_trade.py`의 `HS6_NAMES`).

### 5-4. 필요한 데이터와 갱신

카드 하나만 보여주므로 **최근 발표 월**과 **전년 같은 달** 두 달 치만 있으면 된다.

| 항목 | 내용 |
|---|---|
| 조회 | 관세청 API가 **12개월을 넘는 기간을 거부**하므로(resultCode 99) 12개월 이하 구간 3번으로 나눠 약 27개월치를 받아 최근 월·전년 동월·12개월 추이를 모두 만듦 |
| 확인 주기 | 하루 한 번, 새 달 데이터가 올라왔는지 확인 (접속 시 확인 방식) |
| 수정 반영 | 최근 2개월 값은 수정될 수 있으므로 갱신 때마다 덮어쓰기 |
| 표시 단위 | 달러 금액 ÷ 1,000,000 → 백만 달러, 소수 첫째 자리 |
| 증감률 | (최근 월 수출액 − 전년 동월 수출액) ÷ 전년 동월 수출액 × 100 |

### 5-5. 조회 코드 (예시)

```python
import os
import requests
import xml.etree.ElementTree as ET

TRADE_URL = "기술문서에 적힌 요청 주소"


def fetch_trade(start_yymm, end_yymm, hs_code="3304"):
    params = {
        "serviceKey": os.environ["DATA_GO_KR_KEY"],
        "strtYymm": start_yymm,   # 변수 이름은 기술문서로 확인
        "endYymm": end_yymm,
        "hsSgn": hs_code,
    }
    res = requests.get(TRADE_URL, params=params, timeout=10)
    root = ET.fromstring(res.content)
    return [{
        "yymm": item.findtext("year"),          # 기준 연월 항목명도 확인
        "exp_usd": float(item.findtext("expDlr") or 0),
        "imp_usd": float(item.findtext("impDlr") or 0),
        "balance": float(item.findtext("balPayments") or 0),
    } for item in root.iter("item")]
```

### 5-6. 실패 처리

| 상황 | 화면 동작 |
|---|---|
| API 오류 | 저장된 최근 값 표시 |
| 저장된 값 없음 | 카드에 "수출 실적을 불러오지 못했어요" + K-stat 링크만 표시 |
| 이번 달 데이터 아직 없음 | 가장 최근 발표 월 기준으로 표시 (정상 동작) |

환율 띠도 같은 방식으로, 실패하면 저장된 최근 값을 보여주고 값이 없으면 "환율 정보를 불러오지 못했어요"를 한 줄로 표시한다. 상단이 실패해도 뉴스 영역은 그대로 나와야 한다.

### 5-7. 수출입 자료 수집 방식 (구현)

K-stat 화면을 직접 긁어오지 않는다. K-stat 숫자의 원천인 **관세청 품목별 국가별 수출입실적 API**를 호출해 같은 값을 받고, K-stat은 카드의 링크와 검증용으로만 쓴다. 코드는 `home_data.py`의 `_trade_fetch()` / `refresh_trade()`.

| 단계 | 내용 |
|---|---|
| 요청 주소 | `https://apis.data.go.kr/1220000/nitemtrade/getNitemtradeList` (`.env`의 `TRADE_API_URL`로 바꿀 수 있음) |
| 요청 값 | `serviceKey`(인증키), `strtYymm`·`endYymm`(조회 시작·끝 연월, YYYYMM), `hsSgn`(HS 코드 4단위, 기본 3304) |
| 인증키 처리 | 공공데이터포털이 주는 Encoding 키를 그대로 넣으면 `requests`가 한 번 더 인코딩해 인증 실패가 난다. 키에 `%`가 있으면 `unquote()`로 Decoding 키로 바꿔서 보낸다 |
| 기간 제한 | 12개월을 넘는 기간을 요청하면 `resultCode 99`로 거절된다. 그래서 **12개월 구간 3개**(최근 12개월 / 그 앞 12개월 / 그 앞 12개월 = 36개월)로 나눠 호출하고 합친다. 상세 모달의 24개월 + 전년 동기 비교에 36개월이 필요하다 (5-9) |
| 응답 형식 | XML. `resultCode`가 `00`이 아니면 오류로 처리하고, `<item>`마다 아래 값을 읽는다 |
| 읽는 값 | `year`(연월, "2026.08" 형식), `statCd`(국가 코드), `statCdCntnKor1`(국가명), `hsCd`(HS 6단위 코드), `expDlr`(수출 달러), `impDlr`(수입 달러), `balPayments`(무역수지) |
| 파싱 규칙 | `year`에서 점·하이픈을 지워 6자리 숫자가 아니면(예: "총계" 행) 버린다. `hsCd`가 숫자가 아니면 요청한 4단위 코드를 대신 넣는다. 금액은 쉼표를 지우고 `float`로 바꾸며 실패하면 0으로 둔다 |
| 저장 | SQLite `trade_stats`에 (연월, HS 6단위, 국가 코드) 기본키로 `INSERT OR REPLACE`. 최근 달 값이 수정돼도 다음 수집 때 덮어써진다 |
| 갱신 주기 | 하루 1회(`TRADE_TTL` 24시간). 홈 접속 시 마지막 수집이 24시간 넘었으면 백그라운드 스레드에서 다시 받는다 |
| 실패 | 구간 하나가 실패해도 나머지 구간은 계속 받는다. 전부 실패하면 저장된 값을 그대로 쓰고, 저장된 값도 없으면 카드에 "수출입 실적을 불러오지 못했어요" + K-stat 링크만 표시한다 |

### 5-7-1. 관세청 품목별 수출입실적 — 공식 총계 (교차검증용)

국가 구분 없이 품목별 수출·수입 합계만 주는 별도 API다. 국가별 API를 합산한 값과 **같은 원천의 공식 총계**를 비교할 수 있어 13-1의 "총계 행 vs 국가 합산" 검증을 채운다.

| 항목 | 내용 |
|---|---|
| 이름 | 관세청_품목별 수출입실적(GW) — 공공데이터포털 15101609 |
| 요청 | `https://apis.data.go.kr/1220000/Itemtrade/getItemtradeList`, 변수는 국가별 API와 같음(`strtYymm`, `endYymm`, `hsSgn`) |
| 활용신청 | **같은 인증키로 되지만 데이터셋마다 활용신청이 따로 필요하다.** 신청 전에는 `SERVICE_KEY_IS_NOT_REGISTERED`(403)가 오며, 코드는 이를 감지해 하루 동안 건너뛰고 `meta.trade_totals_status = not_registered`로 기록한다 |
| 수집 | 품목 코드를 받을 때(`_fetch_trade_code`) 같은 36개월 구간으로 함께 받아 `trade_totals`(연월·HS 6단위)에 저장 |
| 사용 | 홈 카드 생성 시 `build_cards(totals=...)`로 넘겨 최근 12개월 각 달의 국가별 합산과 비교. 1% 넘게 다르면 `validation.total_mismatch_months` |

> 담당자 할 일: 공공데이터포털에서 "관세청_품목별 수출입실적(GW)" 활용신청 (개발계정 자동 승인). 승인 뒤 서버를 다시 시작하면 다음 수집부터 총계가 채워진다.

### 5-8. 결측치 처리 (pandas, `home_trade.py`)

카드 3개를 만들기 전에 `build_cards()`가 `trade_stats` 전체 행을 DataFrame으로 읽어 아래 순서로 정리한다. 처리 건수는 `cleaning` 값으로 화면 카드 아래에 "결측 n건 보정 · 제외 n행 · 미보고 n칸 0 처리"처럼 표시한다.

| 순서 | 대상 | 처리 | 이유 |
|---|---|---|---|
| 1. 숫자 변환 | `exp_usd`, `imp_usd`, `balance` | `pd.to_numeric(errors="coerce")` — `'-'`, 빈칸, 문자열은 NaN으로 | API가 실적 없는 칸을 `-`나 빈 값으로 주는 경우가 있어 그대로 두면 합계 계산이 깨진다. NaN으로 바뀐 건수를 `coerced`에 기록 |
| 2. 행 제거 | `yymm`, `country` | 연월이 6자리 숫자가 아니거나 국가 코드가 비어 있거나 `-`인 행 삭제 | 총계 행이나 국가 미상 행이 국가별 합계에 섞이면 이중 계산된다. 지운 행 수는 `dropped`에 기록. 모두 지워지면 `ok=False` |
| 3. 금액 결측 채우기 | `exp_usd`, `imp_usd` | NaN → `0.0` | 통관 실적이 없는 달로 본다. 건수는 `na_amount`에 기록 |
| 3. 무역수지 결측 | `balance` | NaN → `exp_usd − imp_usd`로 재계산 | 수출·수입은 있는데 수지만 빠진 행을 살린다 |
| 3. 국가명 결측 | `country_name` | 빈 값·`-`·NaN → 국가 코드로 대체 | 카드에 이름 칸이 비지 않게 |
| 4. 월 × 국가 표 | `pivot_table` 결과 | 최근 12개월 인덱스로 `reindex`한 뒤 빈 칸 NaN → `0.0` | 어떤 달에 특정 국가 행이 아예 없으면 표에 구멍이 생긴다. 미보고로 보고 0 처리, 칸 수는 `filled_grid`에 기록 |
| 4. 월별 합계 | `groupby("yymm").sum()` | 최근 12개월 + 전년 같은 12개월로 `reindex` 후 NaN → `0.0` | 아직 발표되지 않은 달이 추이 그래프에서 빠지지 않게 |
| 전년 대비 | 증감률 | 전년 값이 없거나 0이면 `change=None`, 화면은 `—` + 회색 | 0으로 나누기 방지. 전년 수출이 0인 국가·품목은 증감률을 표시하지 않는다 |
| 비중·막대 | 상위국·품목 | 합계가 0이면 분모를 1로 두어 0%로 표시 | 데이터가 모두 0일 때 오류 방지 |

정리 후 계산은 다음과 같다.

| 카드 | 계산 |
|---|---|
| 월간 수출입 요약 | 가장 최근 연월(`yymm.max()`)의 수출·수입·수지 합계, 전년 동월 대비 증감률, 최근 12개월 수출액을 최대값 기준 %로 바꾼 막대 그래프, 12개월 누계 |
| 수출 상위국 | 최근 12개월 국가별 수출 합계 상위 3개국. 비중(전체 대비 %), 막대(1위 대비 %), 전년 같은 12개월 대비 증감률 |
| 품목별 수출 | 최근 12개월 HS 6단위별 수출 합계 상위 3개. 품목명은 `HS6_NAMES` 표(코드가 없으면 "HS 코드"로 표시), 비중·막대·증감률은 상위국과 같은 방식 |

`build_cards()` 자체가 예외를 내면 `get_trade_cards()`가 잡아서 "수출입 실적을 분석하지 못했어요"를 돌려주므로 홈의 다른 구역은 영향을 받지 않는다.

숫자가 맞는지 K-stat 등과 대조하는 절차는 13장.


구글 뉴스 RSS는 기사 제목 끝에 ` - 뷰티누리` 같은 매체명이 붙어 오므로 잘라서 저장한다.

**해외 전문지 (선택, 2차)**
영문 화장품 업계지(예: CosmeticsDesign, Cosmetics Business)도 구글 뉴스 RSS의 `site:` 검색으로 받을 수 있다. 제목이 영어라서, 넣는다면 출처 뱃지 옆에 "EN" 표시를 붙인다. 1차 버전에서는 국내 출처만으로 시작한다.

### 6-3. 통합 목록 규칙

| 규칙 | 내용 |
|---|---|
| 통합 | 모든 출처 기사를 한 목록으로 합침 (탭 없음) |
| 정렬 | 게시 시간 최신순 |
| 개수 | 서버는 12건을 보내고, 홈에는 1열로 화면 높이에 맞는 만큼 (약 7~8건) 표시 (2-7 참고) |
| 중복 제거 | 같은 기사 링크는 한 번만 저장 |
| 매체 쏠림 방지 | 출처가 6곳으로 늘어 기사량 차이가 크므로, 홈 목록 12건 중 출처당 최대 3건 |
| 같은 소식 묶기 | 여러 매체가 같은 보도자료를 기사로 내면 제목이 거의 같음 → 제목 유사도가 높으면 가장 먼저 올라온 1건만 표시 |
| 식약처 우선 (선택) | 24시간 이내 식약처 화장품 보도자료가 있으면 목록 위쪽에 고정 |
| 게시 시간 없음 | 처음 수집한 시각으로 대신 저장 |
| 시간 표시 | "3시간 전"처럼 상대 시간, 하루 넘으면 날짜 |

### 6-4. 수집 주기: 6시간

| 항목 | 내용 |
|---|---|
| 주기 | 6시간마다 한 번 수집 |
| 방식 | 홈 접속 시 저장된 뉴스의 수집 시각을 확인해 6시간이 지났으면 새로 수집 |
| 이유 | Render 무료 플랜은 접속이 없으면 서버가 잠들어서, 서버 안에서 돌리는 예약 작업이 제때 실행되지 않을 수 있음. 접속할 때 확인하는 방식은 잠들어도 문제없음 |
| 대기 시간 | 수집이 끝날 때까지 기존 목록을 먼저 보여주고, 백그라운드에서 갱신 (첫 수집 제외) |
| 요청 간격 | 매체 사이에 1~2초 쉬어서 상대 서버에 부담 주지 않기 |

### 6-5. 저작권 · 수집 예절

| 규칙 | 내용 |
|---|---|
| 표시 범위 | 제목, 게시 시간, 매체명, 원문 링크만 표시 |
| 금지 | 기사 본문, 요약문, 사진 복사·저장 금지 (장업신문, 코스인코리아닷컴 등 전문지들이 무단 전재·복사·배포 금지를 명시함) |

### 6-6. 수집 코드 (예시)

```python
import time
import requests
import feedparser
from bs4 import BeautifulSoup
from urllib.parse import urljoin

HEADERS = {"User-Agent": "COSMOA-news-bot (school project)"}
JANGUP_RSS = "여기에 장업신문 RSS 페이지에서 확인한 전체기사 피드 주소"
BEAUTYNURY_RSS = "https://news.google.com/rss/search?q=site:beautynury.com&hl=ko&gl=KR&ceid=KR:ko"


def fetch_jangup():
    feed = feedparser.parse(JANGUP_RSS)
    return [{"source": "장업신문", "title": e.title, "url": e.link,
             "published": e.get("published_parsed")} for e in feed.entries]


def fetch_cmn():
    res = requests.get("https://www.cmn.co.kr/main/", headers=HEADERS, timeout=10)
    soup = BeautifulSoup(res.text, "html.parser")
    items, seen = [], set()
    for a in soup.select('a[href*="news_view.asp?news_idx="]'):
        title = a.get_text(strip=True)
        url = urljoin("https://www.cmn.co.kr", a["href"]).split("&")[0]
        if title and url not in seen:
            seen.add(url)
            items.append({"source": "CMN", "title": title, "url": url, "published": None})
    return items


def fetch_beautynury():
    feed = feedparser.parse(BEAUTYNURY_RSS)
    return [{"source": "뷰티누리", "title": e.title.rsplit(" - ", 1)[0], "url": e.link,
             "published": e.get("published_parsed")} for e in feed.entries]


import re

DATE_RE = re.compile(r"\d{4}-\d{2}-\d{2} \d{2}:\d{2}")


def fetch_mediaon(source, base):
    """코스인코리아닷컴 · 코스모닝 공통 (같은 목록 구조)"""
    res = requests.get(base + "/news/article_list_all.html", headers=HEADERS, timeout=10)
    soup = BeautifulSoup(res.text, "html.parser")
    items, seen = [], set()
    for a in soup.select('a[href*="/news/article.html?no="]'):
        url = urljoin(base, a["href"])
        if url in seen:
            continue
        text = a.get_text(" ", strip=True)
        strong = a.find(["strong", "b"])
        title = strong.get_text(strip=True) if strong else text[:120]
        date = DATE_RE.search(text)
        seen.add(url)
        items.append({"source": source, "title": title, "url": url,
                      "published": date.group() if date else None})
    return items


def fetch_cosinkorea():
    return fetch_mediaon("코스인", "https://www.cosinkorea.com")


def fetch_cosmorning():
    return fetch_mediaon("코스모닝", "https://www.cosmorning.com")


MFDS_RSS = "http://www.mfds.go.kr/www/rss/brd.do?brdId=ntc0021"
MFDS_WORDS = ["화장품", "기능성화장품", "자외선차단", "맞춤형화장품"]


def fetch_mfds():
    feed = feedparser.parse(MFDS_RSS)
    return [{"source": "식약처", "title": e.title, "url": e.link,
             "published": e.get("published_parsed")}
            for e in feed.entries if any(w in e.title for w in MFDS_WORDS)]


def collect_all():
    results = []
    for fetch in (fetch_jangup, fetch_cmn, fetch_beautynury,
                  fetch_cosinkorea, fetch_cosmorning, fetch_mfds):
        try:
            results += fetch()
        except Exception as err:          # 한 매체가 실패해도 나머지는 계속
            print(fetch.__name__, "실패:", err)
        time.sleep(1.5)
    return results
```

CMN 메인에는 같은 기사가 여러 번 나오고 요약문 링크도 섞여 있어서, 링크 기준으로 중복을 제거하고 제목이 너무 긴 항목(요약문)은 걸러낸다. 사이트 구조가 바뀌면 선택자를 다시 맞춰야 한다. 코스인코리아닷컴·코스모닝 목록의 기사 링크 안에는 제목과 요약이 함께 들어 있으므로, 굵은 글씨(제목) 부분만 쓰고 요약은 저장하지 않는다.

## 7. 바이어 현지 시각 기능

### 7-1. 동작 방식

외부 API 없이 **브라우저에서 계산**한다. 시간대 이름(IANA)만 정해 두면 서머타임도 자동으로 반영된다.

| 항목 | 내용 |
|---|---|
| 계산 | 자바스크립트 `Intl.DateTimeFormat`에 시간대 이름을 넣어 현지 시각 계산 |
| 갱신 | 1분마다 다시 계산 (매 분 0초에 맞춰 갱신) |
| 서머타임 | 미국·유럽은 계절에 따라 시차가 바뀌며, 시간대 이름을 쓰면 자동 반영 |
| 시차 표시 | 한국 시각과 현지 시각 차이를 시간 단위로 표시 (예: −13h) |
| 업무 상태 | 현지 월~금 09:00~18:00이면 업무 중, 그 외 업무 외, 토·일은 주말 |

### 7-2. 수출 상위국 모드 (기본)

한국 화장품 수출액이 많은 나라 순서대로 4곳의 시각을 보여준다. 바이어가 많은 나라를 따로 고르지 않아도 되고, 순위가 바뀌면 자동으로 따라간다.

| 항목 | 내용 |
|---|---|
| 데이터 | 5장의 관세청 품목별 국가별 수출입실적 API를 **국가별**로 조회 (HS 3304 또는 팀이 정한 화장품 HS 범위) |
| 기준 기간 | 최근 12개월 누계 수출액 (한 달 실적만 보면 순위가 자주 흔들림) |
| 순위 갱신 | 월 1회, 새 달 수출 실적이 들어올 때 함께 계산 |
| 같은 시간대 합치기 | 홍콩·대만·싱가포르는 중국과 시각이 같으므로 이미 같은 시간대가 있으면 건너뛰고 다음 순위 국가를 넣음 |
| 순위 표시 | 도시명 앞에 작게 순위 표시 (예: 1 중국 · 베이징) |
| 데이터가 없을 때 | 기본 목록 사용: 중국, 미국, 일본, 베트남 (개발 시 K-stat 또는 관세청 조회로 실제 순위 확인 후 확정) |

국가별 조회는 호출 수가 늘어나지만 월 1회만 계산하므로 공공데이터포털 트래픽에 부담이 없다.

## 8. 규제 업데이트 기능

### 8-1. 데이터 출처

| 출처 | 방법 | 내용 |
|---|---|---|
| KOTRA 단신속보뉴스 | 공공데이터포털 Open API (무료, REST, JSON·XML) | KOTRA 해외무역관이 올리는 현지 통상·규제 소식. 수입규제, 정책동향 등 키워드로 분류된 단신 |
| 구글 뉴스 RSS 검색 | RSS | 화장품 규제 키워드 검색 결과 (국내·해외 언론) |
| (선택) KOTRA 해외인증정보 | 공공데이터포털 Open API | 국가별 인증 제도 정보. 규제 탭 담당 팀원과 공유 가능 |
| (선택) 식약처 행정예고 · 법령 RSS | 공식 RSS | 국내 화장품 규제 개정 소식 (`brdId=data0009` 행정예고, `brdId=data0008` 최근 개정 법령). 국가 뱃지는 "한국" |

KOTRA API는 수출입 실적과 같은 공공데이터포털 인증키(`DATA_GO_KR_KEY`)로 신청한다. 요청 주소와 변수 이름은 포털의 참고문서로 확인한다.

구글 뉴스 RSS 검색 주소 예시:

```
https://news.google.com/rss/search?q=화장품+(규제+OR+금지성분+OR+등록+OR+라벨링)&hl=ko&gl=KR&ceid=KR:ko
https://news.google.com/rss/search?q=cosmetics+regulation+(MoCRA+OR+CPNP+OR+NMPA)&hl=en-US&gl=US&ceid=US:en
```

실제 주소에는 한글과 공백을 URL 인코딩해서 넣는다 (`requests`의 `params`를 쓰면 자동 처리).

### 8-2. 화장품 규제 소식 골라내기

KOTRA 단신은 화장품 외 소식도 많으므로 **키워드 필터**를 거친다.

| 단계 | 조건 |
|---|---|
| 1. 화장품 관련 | 제목·요약에 화장품, 코스메틱, cosmetic, 뷰티, 스킨케어, 선크림 등 포함 |
| 2. 규제 관련 | 규제, 금지, 제한, 등록, 인증, 허가, 성분, 표시, 라벨, 개정, 시행, 통관 등 포함 |
| 3. 국가 태그 | 국가명·기관명으로 국가 뱃지 결정 (아래 표) |

### 8-3. "실시간" 수집 방식

완전한 실시간(푸시)은 두 출처 모두 지원하지 않으므로 **짧은 간격으로 새 소식을 확인**하는 방식으로 실시간에 가깝게 만든다.

| 항목 | 내용 |
|---|---|
| 확인 간격 | **1시간** (뉴스의 6시간보다 짧게) |
| 서버 쪽 | 홈 접속 시 마지막 확인이 1시간 넘었으면 새로 수집 (Render 무료 플랜이 잠들어도 동작) |
| 화면 쪽 | 홈을 열어 둔 상태에서는 10분마다 `/api/regulations`를 불러 새 소식이 있으면 목록 맨 위에 추가 |
| 표시 | 제목 줄에 "실시간 · 14:05 확인" |
| 호출량 | 1시간 간격이면 하루 24회 수준으로 공공데이터포털 개발계정 트래픽(하루 10,000건)에 여유 |

### 8-4. 새 소식 알림

| 항목 | 내용 |
|---|---|
| NEW 뱃지 | 게시 24시간 이내 소식 |
| 알림 점 | **미구현.** 상단 알림 버튼 자체를 두지 않았다 |
| 알림 목록 | 미구현 (선택 사항) |
| 관심 국가 (선택) | 미구현 |

### 8-5. 수집 코드 (예시)

```python
import requests
import feedparser

COSMETIC_WORDS = ["화장품", "코스메틱", "cosmetic", "뷰티", "스킨케어", "선크림"]
REG_WORDS = ["규제", "금지", "제한", "등록", "인증", "허가", "성분", "표시", "라벨",
             "개정", "시행", "통관", "regulation", "ban"]
COUNTRY_TAGS = {
    "미국": ["미국", "FDA", "MoCRA"],
    "EU": ["EU", "유럽", "CPNP"],
    "중국": ["중국", "NMPA"],
    "일본": ["일본", "후생노동성"],
    "동남아": ["베트남", "태국", "인도네시아", "말레이시아", "BPOM", "아세안"],
    "중동": ["사우디", "UAE", "SFDA", "할랄"],
}


def is_cosmetic_regulation(text):
    t = text.lower()
    return any(w.lower() in t for w in COSMETIC_WORDS) and any(w.lower() in t for w in REG_WORDS)


def country_tag(text):
    for tag, words in COUNTRY_TAGS.items():
        if any(w.lower() in text.lower() for w in words):
            return tag
    return "기타"


def fetch_google_regulations():
    url = "https://news.google.com/rss/search"
    params = {"q": "화장품 (규제 OR 금지성분 OR 등록 OR 라벨링)",
              "hl": "ko", "gl": "KR", "ceid": "KR:ko"}
    res = requests.get(url, params=params, timeout=10)
    feed = feedparser.parse(res.content)
    items = []
    for e in feed.entries:
        title, _, press = e.title.rpartition(" - ")
        if is_cosmetic_regulation(title):
            items.append({"country": country_tag(title), "title": title,
                          "source": press, "url": e.link,
                          "published": e.get("published_parsed")})
    return items

# KOTRA 단신속보뉴스는 기술문서의 요청 주소·변수로 조회한 뒤
# 제목+요약 텍스트에 is_cosmetic_regulation(), country_tag()를 똑같이 적용한다.
```

### 8-6. 표시 범위와 실패 처리

| 항목 | 내용 |
|---|---|
| 표시 범위 | 제목, 국가, 출처, 시간, 원문 링크만 (뉴스와 같은 저작권 규칙, 6-4 참고) |

```python
def top_export_cities(rows, city_map, n=4):
    # rows: [{"country": "CN", "exp_usd": ...}, ...] 최근 12개월 국가별 합계
    picked, used_tz = [], set()
    for r in sorted(rows, key=lambda x: x["exp_usd"], reverse=True):
        city = city_map.get(r["country"])      # 7-4 표
        if not city or city["tz_offset_key"] in used_tz:
            continue
        used_tz.add(city["tz_offset_key"])       # 같은 시각인 시간대 중복 방지
        picked.append({"rank": len(picked) + 1, **city})
        if len(picked) == n:
            break
    return picked
```

`tz_offset_key`는 한국과의 시차가 같은 시간대를 하나로 묶기 위한 값이다 (예: 베이징·홍콩·타이베이·싱가포르는 같은 값).

**user_settings** — 미구현. 현지 시각 보기 방식과 선택 도시는 브라우저 `localStorage`에 저장한다 (7-3). 외부 DB를 도입하면 이 표로 옮긴다.

수집 데이터(환율·수출입·뉴스·규제)는 모두 필요한 기간이 짧아서, DB 파일이 지워져도 다시 조회해 채우면 된다. 사용자 계정은 지워지면 첫 실행 때 데모 계정만 다시 생기므로, 추가한 계정은 PM이 다시 만들어야 한다.

- [ ] 수출 상위국 모드에서 4곳이 수출액 순서대로, 같은 시간대 중복 없이 나오는지 확인
- [ ] "내가 선택"으로 바꾼 도시가 다시 접속해도 유지되는지 확인
- [ ] 현지 시각이 1분마다 바뀌고, 서머타임 기간에도 시차가 맞는지 확인 (예: 뉴욕 여름 −13h, 겨울 −14h)
- [ ] 현지 주말·업무 외 시간 뱃지가 맞게 나오는지 확인
- [ ] 규제 목록에 화장품과 관계없는 소식이 섞이지 않는지 확인 (키워드 필터)
- [ ] 홈을 열어 둔 채 새 규제 소식이 생기면 10분 안에 목록에 추가되는지 확인
- [ ] 긴 기사 제목이 2줄에서 잘리는지 확인
- [ ] 6시간 안에 다시 접속하면 수집하지 않고 저장된 목록을 쓰는지 확인
- [ ] 환율·수출입 API가 실패해도 뉴스 영역은 정상으로 나오는지 확인
- [ ] 기사 클릭 시 원문이 새 탭으로 열리는지 확인
- [ ] 화면에 기사 본문·사진이 들어가 있지 않은지 확인

## 12. 로그인 화면

### 12-1. 저장 방식 결정

| 항목 | 내용 |
|---|---|
| 결정 | 로그인 정보는 **로컬 SQLite**(`instance/cosmoa.db`의 `users` 표)에 저장한다 |
| 이유 | 팀이 외부 DB 서비스를 아직 배우지 않았다. 지금 단계에서는 각자 PC에서 돌아가면 충분하다 |
| 제약 | DB 파일이 각자 PC에 따로 있으므로 계정도 PC마다 따로다. 팀원끼리 같은 계정 목록을 쓰려면 외부 DB가 필요하다 |
| 교체 계획 | 외부 DB를 배운 뒤 `src/common/auth.py`의 저장 부분만 바꾸고, 화면(`login.html`)과 `app.py`의 Route는 그대로 둔다 |
| 담당 | 로그인은 공통 영역이라 **PM**이 관리한다. 홈 명세서에는 홈이 로그인에 기대는 부분을 적기 위해 함께 둔다 |

### 12-3. 동작

| 단계 | 내용 |
|---|---|
| 접근 제어 | 모든 페이지 Route에 `@login_required`. 세션에 사용자가 없으면 `/login?next=원래경로`로 이동 |
| 로그인 | `POST /login` — 이메일은 소문자로 맞춰 `users`에서 찾고 werkzeug `check_password_hash`로 비교 |
| 성공 | 세션에 `{id, email, name, team}` 저장 후 `next`(같은 사이트 경로만 허용) 또는 홈으로 이동 |
| 실패 | 401 상태로 로그인 화면을 다시 그리고 오류 표시. 입력한 이메일은 유지 |
| 로그인 상태 유지 | 체크 시 세션을 영구 세션으로 두어 **30일** 유지 (`PERMANENT_SESSION_LIFETIME`) |
| 이미 로그인 | `/login`에 들어오면 홈으로 보냄 |
| 로그아웃 | `/logout` — 세션 비우고 `/login`으로 |
| 사이드바 표시 | `app.py`의 `context_processor`가 모든 템플릿에 `current_user`를 넘겨 이름·소속·아바타를 그림 |
| 쿠키 | `HttpOnly`, `SameSite=Lax` |

### 12-4. 계정 관리

| 항목 | 내용 |
|---|---|
| 첫 실행 | `users` 표가 비어 있으면 데모 계정을 자동 생성. 값은 `.env`의 `COSMOA_DEMO_EMAIL / COSMOA_DEMO_PASSWORD / COSMOA_DEMO_NAME / COSMOA_DEMO_TEAM`, 비어 있으면 `demo@costd.kr / cosmoa1234 / 데모 사용자 / 해외영업팀` |
| 계정 추가 | 회원가입 화면이 없으므로 PM이 `auth.create_user(email, password, name, team)`으로 추가한다 (Python 셸 또는 간단한 스크립트) |
| 비밀번호 | 해시만 저장. 비밀번호 변경·찾기 기능은 없음 |
| 보안 주의 | `instance/`와 `.env`는 Git에 올리지 않는다. 데모 비밀번호는 개발용이므로 배포 시 반드시 바꾼다 |

## 13. 데이터 교차검증

홈 화면은 외부 출처 4종(수출입은행, 관세청, 뉴스 매체 6곳, 구글 뉴스 RSS/KOTRA)의 값을 그대로 보여주므로, **틀린 값이 그대로 화면에 나가지 않도록** 코드 안에서 자동으로 거르는 것과, 담당자가 손으로 확인하는 것을 나눠서 정리한다. "교차검증"은 같은 값을 **다른 경로로 한 번 더 확인**한다는 뜻으로 쓴다.

### 13-1. 자동 검증 (코드에 들어 있는 것)

**환율** (`home_data.py` 4장 구현)

| 검증 | 방법 | 결과 |
|---|---|---|
| 응답 상태 | 첫 항목의 `result`가 1이 아니면 오류로 본다 (인증키 오류, 호출 한도 초과 등) | 저장하지 않고 직전 값 유지 |
| 값 형식 | 통화 코드가 비어 있거나 `deal_bas_r`를 숫자로 못 바꾸면 그 통화만 건너뜀 | 화면에서 해당 통화 빠짐 |
| 날짜 교차 | 오늘 값이 비어 있으면 하루씩 거슬러 값이 있는 날을 찾고(최대 14일), **최근 영업일과 직전 영업일 두 날짜**를 따로 확보해 등락률을 계산 | 두 날짜가 모두 있어야 등락률 표시, 하나면 `—` |
| 휴일 표식 | 값이 없는 날은 `__EMPTY__` 행을 남겨 같은 날짜를 다시 호출하지 않음 | 호출 한도 절약 |
| 이른 시간 재확인 | 오늘 값이 아직 없고 12시 전이면 "오늘 확인함" 표식을 남기지 않아 낮에 다시 조회 | 오전 갱신 반영 |
| 이상값 표시 | 전일 대비 **±10% 이상**(`RATE_WARN_PCT`) 움직인 통화는 `warning=True`로 내려주고 로그 경고 | 환율 띠에 주황 `!` 표시와 툴팁 "값 확인 필요". 값은 숨기지 않음 |

**화장품 수출입** (`home_data.py` 5-7, `home_trade.py` 5-8)

| 검증 | 방법 | 결과 |
|---|---|---|
| 응답 상태 | `resultCode`가 `00`이 아니면 오류 (12개월 초과 요청은 `99`) | 해당 구간만 실패, 나머지 구간은 저장 |
| 연월 형식 | `year` 값이 6자리 숫자로 정리되지 않으면(총계 행 등) 버림 | 합계 이중 계산 방지 |
| HS 코드 교차 | 응답의 `hsCd`(6단위)가 숫자가 아니면 요청한 4단위 코드로 대체 | 품목 카드에 빈 코드가 생기지 않음 |
| 구간 겹침 | 3개 조회 구간이 겹치지 않게 잡고, 저장 기본키(연월·HS·국가)로 `INSERT OR REPLACE` | 같은 달이 두 번 들어와도 한 행 |
| 총계 vs 국가 합산 | **품목별 수출입실적 API의 공식 총계**(5-7-1)를 최근 12개월 각 달의 국가별 합산과 비교해 1% 넘게 다른 달을 `validation.total_mismatch_months`에 기록하고 로그 경고. 총계 API가 미신청 상태면 응답 안 "전체" 행으로 대체, 그것도 없으면 건너뜀(`total_rows=0`) | 카드 정리 문구에 "총계 불일치 n개월", `validation.total_source`에 어느 총계를 썼는지 |
| 무역수지 교차 | 수지 값이 있는 행에서 `수출 − 수입`과 1달러 넘게 다르면 `validation.balance_mismatch_rows`로 세고 로그 경고 (값은 API 원본 유지). 비어 있는 행만 `수출 − 수입`으로 채움 (5-8) | 카드 정리 문구에 "수지 불일치 n행" |
| 전년 비교 분모 | 전년 값이 0이거나 없으면 증감률을 계산하지 않음 | `—` 표시, 0으로 나누기 없음 |
| 정리 건수 노출 | 결측 보정·제외·미보고 칸 수를 `cleaning.text`로 카드에 표시 | 이상하게 많으면 담당자가 바로 알 수 있음 |

**화장품 최신 뉴스** (`home_data.py` 6장)

| 검증 | 방법 | 결과 |
|---|---|---|
| 출처 6곳 교차 | 매체별 수집 결과를 한 표(`news_items`)에 모아 URL 기본키로 중복 저장 방지 | 같은 링크는 1건 |
| 같은 소식 교차 | 제목에서 공백·기호를 지운 뒤 `difflib` 유사도 0.8 이상이면 같은 보도자료로 보고 먼저 나온 1건만 표시 (6-3) | 여러 매체가 같은 보도자료를 쓴 경우 1건 |
| 매체 쏠림 | 홈 목록은 출처당 최대 3건 | 한 매체가 목록 독점 불가 |

| 웹 검색 결합 | 더보기 검색 시 구글 뉴스 결과를 합칠 때도 같은 URL·제목 유사도 규칙 적용 | 수집 기사와 웹 기사 중복 제거 |
| 부분 실패 | 매체 하나가 실패해도 나머지 저장, 전체 실패 시 갱신 시각을 바꾸지 않음 | 화면은 직전 목록 + 이전 업데이트 시각 |

| 검증 | 방법 | 결과 |
|---|---|---|
| 출처 2곳 교차 | 구글 뉴스 RSS(한·영 검색 2종)와 KOTRA 단신에 **같은 키워드 필터**(`is_cosmetic_regulation`)와 **같은 국가 태거**(`country_tag`)를 적용 | 출처가 달라도 같은 기준으로 걸러짐 |

### 13-2. 수동 검증 (담당자가 확인하는 것)

자동 검증은 형식과 중복만 잡는다. **숫자가 맞는지**는 다른 출처와 직접 비교한다.

| 대상 | 비교 출처 | 방법 | 허용 차이 |
|---|---|---|---|
| 월간 수출·수입액 | **K-stat**(https://stat.kita.net/) 품목별 수출입 → HS 3304, 같은 달 | 카드의 백만 달러 값과 비교. 카드 아래 K-stat 링크로 바로 이동 | 반올림 차이(±0.1M) 이내. 최근 2개월은 확정 전 수정치가 있을 수 있음 |
| 수출 상위국 순위·금액 | K-stat 국가별 수출입 → HS 3304, 최근 12개월 | 상위 3개국 순서와 금액 비교 | 순서 동일, 금액 반올림 차이 |
| 품목별 수출 | 관세청 수출입무역통계(https://tradedata.go.kr) HS 6단위 | 상위 3개 코드와 품목명 비교 | 코드 동일. 품목명은 `HS6_NAMES` 표를 관세청 품목표와 맞춤 |
| 환율 | 수출입은행 환율 페이지 또는 네이버 환율(매매기준율) | 통화 6개 값과 기준일 비교 | 같은 기준일이면 동일해야 함. 다르면 기준일 확인 |
| 환율 등락률 | 수출입은행 전일 값 | 직전 영업일 값으로 다시 계산 | 소수 둘째 자리 이내 |
| 뉴스 | 원문 기사 | 목록 5건 이상 클릭해 제목·매체·시각이 원문과 같은지 확인 | 제목 앞뒤 매체명이 잘려 있어야 함 |
| 규제 | 원문 + 국가별 인허가규제 담당(B) | 국가 뱃지가 원문 내용과 맞는지, 화장품 무관 기사가 섞였는지 확인 | 틀린 태그·무관 기사 발견 시 8-2 키워드 표 수정 |
| 현지 시각 | 구글 "뉴욕 현재 시각" 등 | 4개 도시 시각·업무 상태 비교 | 분 단위 동일 |

### 13-3. 검증 결과를 보는 곳

| 위치 | 내용 |
|---|---|
| 서버 로그 | `cosmoa.home` 로거. 수집 건수, 구간별 실패 사유, 도시 표에 없는 국가 코드 |
| 카드 하단 정리 문구 | "결측 n건 보정 · 제외 n행 · 미보고 n칸 0 처리" — 평소보다 크게 늘면 API 응답 형식이 바뀐 신호 |
| `/api/home/data` | 화면에 그리기 전 원본 JSON. `rates.date`, `trade_cards.cleaning`, `trade_cards.validation`, `rates.items[].warning`, `news.updated_at`, `regulations.checked_at`, `refreshing`을 직접 확인 |
| `/api/home/validation` | **검증 요약 전용 API** (로그인 필요). 구역별 `last_success` / `last_try` / `stale`(갱신 주기 초과) / `failing`(마지막 시도가 성공보다 뒤) / `ok`, 환율 `warnings`(급변 통화), 수출입 `rows`·`months`·`cleaning`·`validation`, 뉴스 매체별 건수와 `missing_sources`(한 건도 없는 매체), 규제 국가별·출처별 건수와 `kotra_configured`. 발표·점검 때 이 주소 하나로 상태 확인 |
| 갱신 시각 표시 | 환율 "n/n 기준", 뉴스 "HH:MM 업데이트", 규제 "HH:MM 확인"이 오래됐으면 수집 실패 중 |

### 13-4. 한계와 추후 과제

| 항목 | 현재 | 보완 방향 |
|---|---|---|
| 총계 vs 국가 합산 | 품목별 API(5-7-1)로 구현했으나 **공공데이터포털 활용신청 전**이라 아직 동작하지 않음 | 활용신청 승인 후 자동 동작 |
| 무역수지 | 불일치 행 수만 세고 어느 행인지는 API·로그에 남기지 않음 | 불일치 상위 몇 건의 연월·국가를 `validation`에 포함 |
| K-stat 대조 | 수동 | K-stat은 공개 API가 없어 자동화하지 않음 (5-1 결정) |
| 환율 이상값 | ±10% 고정 임계값. 통화별 변동성 차이를 반영하지 않음 | 통화별 임계값 또는 최근 30일 표준편차 기준 |
| 검증 API 표시 | `/api/home/validation`은 JSON만 제공하고 화면은 없음 | 필요하면 PM과 상의해 점검용 화면 추가 |
| 뉴스 제목 유사도 | 0.8 고정. 짧은 제목은 다른 기사가 같은 것으로 묶일 수 있음 | 제목 길이에 따라 임계값 조정 |
| 규제 국가 태그 | 첫 번째로 매칭된 국가 하나만 | 여러 나라가 언급된 기사는 다중 태그 |
| 뉴스·규제 사실 확인 | 제목·링크만 다루므로 내용의 정확성은 검증하지 않음 | 화면에 "원문 확인" 안내 유지 |
