# 국가별 인허가 규제

## 1. 페이지 목적

화장품 OEM·ODM 해외영업 담당자가 성분을 직접 검색하거나 개발요청서·성분표를 이 페이지에 업로드하여, 대상 시장의 성분 규제 정보와 추가 확인 사항을 조회한다.

- **문서 성격**: 이 문서는 `/regulatory` 페이지 기능 구현의 기준 명세이다. 기능 요구사항은 README 규칙에 따라 이 문서를 최우선으로 따른다. 현재 성분 직접 검색(한글·영문 INCI 검색·입력 중 자동완성·후보 선택·시장별 규제 조회·결과 카드)과 파일 탭의 **업로드 → 시트 선택 → 성분·함량 추출 → 확인·수정 → 성분 확인(API 매칭) → 확정 성분 규제 일괄 조회 → 결과 표·상세**(텍스트 PDF·.xlsx)는 구현되어 있다. 스캔 PDF·PNG/JPG 이미지는 서버 로컬 OCR(Tesseract)로 읽어 같은 흐름에 연결된다(2026-09-23). 중간 포함 검색, 함량 기준 비교(검토 상태), 시장 자동 선택은 **미구현** 상태이다.
- **확정 요구사항**: 아래에서 별도로 확인 예정·협의 사항으로 표시하지 않은 기능은 초기 구현 목표이다. PDF(텍스트·스캔), Excel(.xlsx), 이미지(.jpg·.jpeg·.png)를 모두 포함한다.
- **범위 제외**: 문서 전체 분석·요약·번역·개발요청서 생성, 다른 담당자 페이지와의 파일 연동, 성분 조합의 안전성·규제 적합성 자동 판정.
- 결과는 조회된 근거와 입력 조건의 비교를 지원한다. 최종 수출 가능 여부, 제품 전체의 적법성 또는 안전성을 확정하지 않는다. 부분 개발요청서는 완성 처방으로 취급하지 않는다.
- **사전검토 보조 도구 (2026-09-25 명시)**: 이 페이지는 해외영업 담당자가 성분 규제를 사전검토하는 보조 도구이며, 최종 처방과 수출 대상국 규정의 적합성은 연구·규제 담당자가 검토한다. 대시보드에서 조회되지 않는 성분이나 더 자세한 제한사항은 식약처 공식 조회 페이지(의약품안전나라 ‘화장품 사용제한 원료’, `https://nedrug.mfds.go.kr/pbp/CCBDF01`)로 연결해 사용자가 직접 추가 확인한다. 조회 결과가 없다고 사용 가능하거나 규제가 없다는 뜻이 아니며, 식약처 사용제한 원료 조회만으로 모든 해외 시장의 적합성이 확정되지도 않는다. ‘최신 규제 검증 완료’·‘수출 가능’ 같은 단정 문구는 쓰지 않는다.
- **확인 예정**: K뷰티 API의 기본 주소·인증 헤더·한글 검색·국가별 규제 조회 호출은 9항의 확인 사례로 기록했다. 영문 INCI 검색, 부분 검색, 동의어 범위, 호출 제한, 아세안 공통·개별 국가 규정 범위, 추출 도구 및 운영 제한 값은 확인 예정이다. 확인 전에는 해당 범위를 제공한다고 단정하지 않는다.

- 기능 코드, Python 모듈, API 설명, 응답 예시, 테스트 코드, 샘플 문서는 모두 `src/02_regulatory/` 안에 생성한다.

- 사용자가 실제로 업로드한 원본과 처리 중 임시 파일은 `src/` 등 공개 자산 경로에 저장하지 않는다. 저장 위치는 13항을 따른다.

## 3. URL

- 기존 페이지 URL은 `/regulatory`, endpoint는 `regulatory`이며 변경하지 않는다.
- 새로 추가하는 API Route는 `/api/regulatory/` 접두사를 사용한다.
- 성분명 후보 검색, 파일 추출 요청, 국가별 규제 조회 요청은 각각 별도 처리로 구분한다. 세부 Route, HTTP 메서드, 요청·응답 계약은 구현 시 확정하여 `src/02_regulatory/api_reference.md`에 기록한다. 이 문서의 화면 항목은 Route 계약을 의미하지 않는다.
- 페이지 이동과 정적 자산 경로는 기존 `url_for()` 방식을 사용한다.

## 4. 사용자

- 화장품 OEM·ODM 해외영업 담당자: 바이어 요청 성분·함량·제품 조건을 확인하고 대상 시장의 근거 자료와 추가 확인 사항을 검토한다.
- 직접 검색은 개별 성분 확인에, 파일 일괄 조회는 개발요청서·성분표에 기재된 여러 요청 성분 확인에 사용한다.
- 규제 정보가 조회되었다는 사실과 해당 입력이 기준을 충족한다는 의미를 구분해 이해할 수 있어야 한다. 검토 범위와 미확인 사항을 결과에 함께 표시한다.

## 5. 주요 기능

**성분 직접 검색**

- 탭 안에서 국가/시장을 선택하고 한국어 성분명 또는 영문 성분명(INCI)을 입력하여 검색 버튼으로 조회한다. 두 언어 지원은 확정 구현 목표이다.
- 입력 앞뒤 공백을 제거하고 영문 검색은 대소문자를 구분하지 않는다. 검증된 한글명·영문명·동의어를 동일 성분에 연결하며 AI 번역만으로 성분의 동일성을 확정하지 않는다.
- 직접 검색의 입력은 성분명과 국가/시장뿐이다. 함량·제품 유형·사용 조건 입력과 기준 비교(검토 상태)는 직접 검색에서 제공하지 않는다. (2026-09-23 요구사항 변경. 함량 추출·수정·비교는 파일 일괄 조회 요구사항으로 유지)
- 결과는 성분명·영문명·조회 시장·조회 상태·규제 유형과 규제 조건을 표시한다. 규제 조건은 API 원문(`limit_condition`)을 결과 카드 본문에 충분한 폭으로 보여주고, 원문 구조가 명확히 구분되는 경우에만 언어별(영문 전체가 위, 한국어 전체가 아래. 한 언어만 제공되면 그 언어만)로 배치한 뒤 적용 제품·최대 농도·사용 조건·주의 문구로 나눠 표시하고, 분류가 불확실한 내용은 ‘기타 원문’에 누락 없이 둔다. 번역·요약은 하지 않으며 한국어 문장 안의 영문 성분명·단위를 분리하지 않는다. 수치·단위·레티놀당량 같은 기준과 적용 제품의 대응 표기((a)/(b) 등)는 원문 그대로 보존하며, 구분이 불확실하면 요약하지 않고 원문을 읽기 좋게 표시한다. 특정 성분에 맞춘 조건을 하드코딩하거나 API에 없는 정보를 생성하지 않는다. 출처·날짜·원문 전체는 상세 Modal에서 확인한다.
- **확인 사례 (2026-09-23)**: 한글 검색 `/v1/ingredient/kr?q=`와 영문 INCI 검색 `/v1/ingredient/inci?q=`는 공개 README 문서와 실제 호출로 확인했다(9항). 둘 다 **시작 일치**이며 영문은 대소문자를 무시한다. 한글 엔드포인트에 영문을 넣으면 0건이므로 서버가 입력의 한글 포함 여부로 엔드포인트를 골라 **1회만** 호출한다. 검색어 최소 길이는 API 문서 기준 2글자다.
- **확인 예정**: 동의어 범위·식별번호 검색 제공 여부, 중간 포함 검색(`/v1/ingredient/search`, PRO+ 전용으로 문서화됨)의 사용 여부. 매핑 데이터 보완은 이 단계에서 필요하지 않아 도입하지 않았다.

**성분명 자동완성**

- 앞뒤 공백 제거 후 2글자 이상 입력하면 검색창 아래에 선택 가능한 자동완성 드롭다운을 표시한다. 한글·영문 입력 모두 지원하며, 예를 들어 ‘에탄’ 입력 시 데이터에 등록된 ‘에탄올’을 후보로 표시한다.
- 후보는 한글명과 영문 INCI명을 함께 표시한다. 한글명이 없으면 영문명만 표시하며 한글명을 만들어내지 않는다.
- 정확히 일치하는 후보 → 입력어로 시작하는 후보 → 입력어가 포함된 후보 순으로 최대 10개 표시한다. 동일 성분의 여러 이름이 일치해도 후보는 성분별로 중복 제거한다.
- 마우스 클릭 또는 방향키 위·아래 이동 후 Enter로 후보를 선택하면 해당 성분이 선택되고 목록이 닫힌다. Esc 또는 검색창·후보 목록 바깥 클릭으로도 닫는다.
- 선택 후 검색어를 수정하면 기존 성분 선택을 해제한다. 후보가 없으면 ‘일치하는 성분이 없습니다’를 표시한다.
- 자동완성은 성분명 후보 검색이다. 후보 선택만으로 국가별 규제 조회를 실행하지 않으며 검색 버튼으로 별도 실행한다. 후보를 선택하지 않고 검색해도 성분 매칭을 시도하고 여러 후보이면 사용자 선택을 요청한다.

**파일로 일괄 조회**

- 다른 페이지를 거치지 않고 개발요청서 또는 성분표를 직접 업로드한다.
- 텍스트 PDF, 스캔 PDF, .xlsx, .jpg, .jpeg, .png 모두 지원한다. **현재 구현(2026-09-23)**: 텍스트 PDF(pypdf), .xlsx(openpyxl), 스캔 PDF·PNG/JPG(서버 로컬 Tesseract OCR, 한글+영문). PDF 는 쪽마다 읽힌 글자 수를 보고 20자 미만인 쪽에만 OCR 을 적용해 한 쪽을 두 번 읽지 않는다. OCR 로 읽은 행은 모두 ‘확인 필요(OCR)’로 표시하며 인식 오류를 임의 확정하지 않는다. **표 복원(2026-09-23 보완)**: 괘선(테두리)이 있는 표에서 Tesseract 가 제목 행·일부 행을 깨뜨리던 문제를 위해 (1) 회색조·괘선 제거·확대 전처리, (2) 단어 위치(image_to_data)로 줄과 셀을 복원하고 제목 셀의 x 범위로 열을 배정, (3) 제목 변형(성분명·한글/영문 성분명·INCI Name·원료명 등, 대소문자·공백·줄바꿈·끝 구두점 정규화, 한글 음절 사이 공백 제거) 처리, (4) 같은 행의 한글명·영문명은 한 성분(`name_raw`·`inci_raw`)으로, 행 번호 열이 있을 때 번호 없는 줄은 앞 행의 두 줄 셀로 병합, (5) 합계·문서 정보·결재란 행 제외, (6) 제목을 못 찾으면 어떤 줄도 성분으로 등록하지 않고 ‘표 구조 인식 실패’로 안내(글자 인식 실패와 구분), (7) 셀 신뢰도가 낮거나 글자가 깨진 행은 ‘인식 신뢰도 낮음’ 사유를 붙인다. 첫 인식(psm 6)에서 제목을 못 찾으면 psm 4 로 한 번 더 시도한다. OCR 이 준비되지 않은 서버에서는 이미지·스캔 전용 PDF 에 설치 안내(503)를 돌려주고, 혼합 PDF 는 텍스트 쪽만 처리한 뒤 읽지 않은 쪽을 표시한다. 외부 AI/OCR 서비스 전송은 없다.
- 파일 유형에 맞게 텍스트·표 추출 또는 OCR/이미지 인식을 수행한다. Excel에 여러 시트가 있으면 분석할 시트를 사용자가 선택한다.
- 규제 조회에 필요한 시장, 요청 성분명, 함량과 기준, 제품 유형·사용 조건만 추출한다. 확인·수정 후 규제 조회를 실행한다. **현재 구현**: 성분명·함량(문서에 있을 때만, 원문 그대로)·문서 비고·원문 위치를 추출하고, 문서에 적힌 국가와 제품 유형·사용 조건은 라벨 행이 있을 때 원문 텍스트로만 표시한다(시장 자동 선택 없음). 성분 구분·함량 기준 열은 이번 단계에서 두지 않는다.
- 명확한 문서 시장을 자동 선택하고 사용자가 변경할 수 있게 한다. 미기재·모호함·미지원 시장은 임의 대체하지 않는다.
- 추출·수정 정보를 유지하여 파일을 다시 업로드하지 않고 시장을 바꿔 다시 조회한다.

추출 결과 확인 화면에서 성분·함량·기준·구분·제품 조건과 시장을 수정할 수 있다. 판독 불가 항목은 직접 입력하거나 재업로드할 수 있다. 사용 제외 성분은 별도 목록으로 보이며 기본 조회 대상에서 제외한다. 선택 성분도 요청 성분임을 유지하고 실제 조회 포함 여부를 확인할 수 있게 한다.

**이번 단계 제한값 (2026-09-23 확정, `regulatory_extract.py`·`regulatory_ocr.py` 상수)**: 파일 1개 · 10 MB 이하 · PDF 20쪽 이하 · Excel 시트 20개 이하, 시트당 앞 2,000행 스캔 · 성분 행 최대 200개(초과분은 잘라내고 안내). **OCR**: 파일당 최대 10쪽, 쪽당 25초, 파일당 총 90초, 이미지 3,000만 화소(약 5,500×5,500) 초과 거부, 긴 변 2,600px 초과는 축소해 인식, PDF 쪽은 약 200 dpi 로 렌더링. 업로드 영역과 오류 메시지에 같은 값을 안내한다. 시트 선택: 시트가 2개 이상이면 서버가 시트 목록만 돌려주고, 사용자가 고른 뒤 같은 파일을 시트명과 함께 다시 보낸다(서버에 파일을 남기지 않기 위함).

## 7. 처리 과정

**직접 검색 흐름**

1. 검색 입력의 앞뒤 공백을 제거하고 영문 대소문자를 구분하지 않는 검색값을 사용한다. 원래 표시명은 보존한다. 입력이 바뀌면 기존 선택 성분과 이전 후보 요청의 유효성을 해제한다.
2. 2글자 이상이고 입력이 멈춘 뒤 약 300ms 후 성분명 후보를 조회한다. 한글 조합 중에는 요청을 보내지 않고, 조합 완료 후 길이 조건과 대기 시간을 적용한다. 2글자 미만이면 후보 요청을 하지 않고 목록을 닫는다. (2026-09-23 변경) API 문서가 검색어 최소 2글자를 요구하므로 서버 Route도 2글자 미만을 검증 오류로 돌려주며, 직접 검색 버튼도 같은 조건을 따른다.
3. 입력에 한글이 있으면 한글 엔드포인트, 없으면 영문 INCI 엔드포인트를 호출한다(1회). 이름별 일치 유형 중 가장 높은 우선순위를 해당 성분에 적용하고 `code` 기준 중복 제거 후 최대 10개를 표시한다. 등록되지 않은 후보는 생성하지 않는다. 두 엔드포인트 모두 시작 일치라 중간 포함 입력(예: ‘티놀’)은 후보가 없다.
4. 현재 검색어에 대응하는 최신 응답만 목록에 반영한다. 이전 검색어의 늦은 응답을 무시하며, 선택·Esc·바깥 클릭으로 닫힌 목록이 진행 중 응답으로 다시 열리지 않게 한다.
5. 클릭 또는 방향키 위·아래와 Enter로 후보를 선택하고 목록을 닫는다. 후보 선택용 Enter는 폼 제출·규제 조회로 이어지지 않는다. 선택한 성분과 표시 검색어를 연결해 유지하되 입력 수정 시 선택을 해제한다.
6. 사용자가 검색 버튼을 누르면 국가/시장과 성분명 입력을 검증한다. 후보를 선택하지 않았으면 현재 입력값으로 매칭을 시도한다. 여러 후보이면 실제 후보 중 사용자 선택을 받고 임의로 첫 후보를 확정하지 않는다. 확인 후 검색 버튼으로 규제 조회를 실행한다.
7. 서버에서 확정된 성분 식별값(예: API 검색 결과의 `code`)과 선택 시장으로 규제 정보를 조회한다. 자동완성 요청이나 후보 선택 자체는 규제 조회를 발생시키지 않는다.
8. 조회 상태(규제 정보 조회됨 / 규제 데이터 미확인 / 판단 보류 / API 오류)와 규제 유형·규제 조건 원문을 표시한다. 직접 검색에서는 기준 비교·검토 상태를 표시하지 않으며 제품 적합성·안전성을 판정하지 않는다.

**파일 흐름: 업로드 → 추출 정보 확인 → 규제 조회 → 결과**

1. 파일 형식·실제 읽기 가능 여부와 확정된 제한을 서버에서 검증한다. (구현: 확장자 + 파일 서명(%PDF / zip 안 xl/workbook.xml) + 용량·쪽수·시트 수. 암호 PDF·손상 파일은 읽기 실패로 구분)
2. 텍스트 PDF는 텍스트·표를 추출하고, 스캔 PDF와 이미지는 OCR/이미지 인식을 수행한다. 읽히지 않는 부분은 추정하지 않고 표시한다. .xlsx는 시트 목록 확인 및 선택 후 해당 시트의 표를 추출한다. (구현: PDF 는 레이아웃 텍스트에서 `INCI name / Ingredient / 성분명 / 원료명` 등 **제목이 있는 표만** 읽고, 텍스트가 거의 없는 PDF 는 스캔 PDF 로 보고 미지원 안내. 표 제목이 없으면 성분을 만들지 않고 ‘추출 결과 없음’)
3. 규제 조회용 항목을 추출하고 원문 위치(확인 가능한 페이지·시트·셀 등), 원문값, 불명확한 부분을 함께 보관한다. (구현: 문장처럼 보이는 이름, 형식이 다른 함량, 빈 이름은 ‘확인 필요’와 사유로 표시. 함량 미기재는 `null`이며 0 으로 바꾸지 않는다)
4. 문서에 명시된 대상 시장을 식별한다. 단순 주소·참고 국가 등을 판매 대상이라고 임의 확정하지 않으며, 지원 시장 매핑이 명확할 때 자동 선택한다.
5. 사용자가 시장·성분·함량·기준·제품 조건·조회 포함 여부를 확인하고 수정한다. 입력이 불충분한 항목은 확인 필요 상태로 남기며, 사용자가 조회를 실행하기 전 규제 일괄 조회를 시작하지 않는다.
6. 확인된 조회 대상을 성분별로 매칭·조회한다. 한 항목의 매칭 실패나 API 오류가 나머지 조회를 중단시키지 않게 한다. **구현(2026-09-23)**: ‘성분 확인’ 버튼이 조회 포함 행의 성분명으로 기존 후보 검색 Route 를 **순차** 호출한다(같은 이름은 1회). 정확히 일치(공백·대소문자 무시)하는 후보가 하나일 때만 자동 확정하고, 여러 후보는 행의 목록에서 사용자가 선택하며, 후보가 없으면 ‘성분 확인 필요’다. 유사 이름을 임의 확정하지 않는다. 성분명을 수정하면 그 행의 매칭·조회 결과를 지운다. ‘확정 성분 규제 조회’는 확정 행만, (성분 코드, 시장)당 1회 순차 호출해 각 행에 결과를 연결한다. 호출 제한이 불명확해 병렬 호출은 하지 않으며, 429(rate_limit)가 오면 즉시 중단하고 남은 항목을 실패로 표시한다(자동 재시도 없음). 실패 행만 ‘실패 항목 재시도’로 다시 조회하고 성공 결과는 유지한다.
7. 규제 정보, 조건 비교와 미확인 이유를 결과에 표시한다. 재조회는 수정된 조건을 사용하며 이전 응답이 최신 결과를 덮어쓰지 않게 한다. **구현**: 시장·성분 목록·매칭이 바뀌면 ‘이전 조건의 결과’ 안내를 표시하고, 늦게 도착한 응답은 조회 순번으로 무시한다. 조건 비교(검토 상태)는 미구현이며 함량은 상세의 ‘문서 함량(참고)’로만 표시한다.

**국가 자동 선택 규칙**

- 시장 코드와 문서 국가의 매핑을 적용한다. 예를 들어 문서에 Singapore, Malaysia, Thailand가 대상 국가로 명시되어 있고 아세안 매핑이 적용되면 ‘아세안’을 자동 선택하고 ‘문서에 명시된 국가: 싱가포르·말레이시아·태국’을 표시한다.
- `ASEAN` 조회의 적용 규정 범위가 확인되지 않은 상태에서는 ‘아세안 시장 조회 / 적용 규정 범위 확인 필요’로 표시한다.
- `ASEAN` 조회가 아세안 공통 기준을 제공한다는 근거가 실제로 확인된 경우에만 ‘아세안 공통 기준 조회’로 표시한다.
- 개별 국가 규정의 확인 여부는 위 표시와 별도로 표시한다.
- 국가가 없거나 모호하면 미선택 상태에서 사용자 선택을 받는다. 여러 시장으로 나뉘어 하나로 확정할 수 없으면 감지된 국가를 보여주고 조회 시장을 선택받는다.
- 미지원 시장은 원문 시장과 함께 미지원 안내를 표시한다. 다른 지원 시장으로 조용히 대체하지 않는다. 사용자가 직접 다른 시장을 선택하면 원문 시장과 현재 선택의 차이를 표시한다.
- 시장 변경 시 추출·수정값은 유지하고 기존 결과는 이전 시장의 결과임을 표시하여 재조회를 요구한다. 새 시장의 결과처럼 재사용하지 않는다.

## 8. 출력 결과

**직접 검색 결과 카드**

직접 검색은 성분 하나를 조회하므로 표 대신 결과 카드 한 장으로 표시한다.

- 상단: 성분명(한글명)·영문 INCI명·조회 시장, 서비스 조회 시각.
- 조회 상태: 규제 정보 조회됨 / 규제 데이터 미확인 / 판단 보류(확인되지 않은 응답) / API 오류. ‘규제 정보 조회됨’은 허용·안전처럼 보이는 색으로 강조하지 않는다.
- 규제 유형: 응답의 `regulate_type` 원문.
- 규제 조건: `limit_condition` 원문을 카드 본문에 충분한 폭으로 표시한다. 원문이 ‘태그·라벨 : 값’ 블록으로 명확히 구분되면 언어별(English · API 제공 영문 → 한국어 · API 제공 한국어, 제목·구분선·여백으로 구분)로 배치한 뒤 적용 제품·부위·최대 농도·사용 조건·주의 문구·기타 원문으로 묶어 보여주고, (a)/(b) 같은 대응 표기와 수치·단위·기준은 원문 그대로 둔다. 하나라도 구분할 수 없으면 나누지 않고 원문 전체를 읽기 좋게 표시한다. 요약·환산·재해석·성분별 하드코딩을 하지 않는다.
- 상세 Modal: 검색어·조회 시장, 매칭 성분(code)·매칭 방식·API 레코드 갱신일, 조회 상태·응답 상태값·규제 구분·고시 성분명·규제 조건 원문 전체·단서 조항·실제 조회 범위·API 안내 문구, 출처·제공원 고지·규제 자료 갱신일·서비스 조회 시각·자체 검증일.
- 검토 상태·기준 충족 여부·입력 부족 안내는 직접 검색에 없다.
- 카드 하단 순서(2026-09-25 정리): ① 메타정보(실제 조회 범위·출처·확보 시각·갱신 안내·시각 안내) → ② 버튼 행: ‘규제 원문·출처 보기’(내부 상세 Modal, `<button>`)와 ‘식약처에서 사용제한 원료 확인’(외부 링크 `<a>`, 외부 링크 아이콘)을 같은 공통 보조 버튼(`.btn-soft`)으로 나란히 → ③ 사전검토 안내 한 문장과 작은 도움말. 별도 안내 패널·버튼 이름과 겹치는 설명 문구는 두지 않는다. 조회 상태와 무관하게(조회됨·출처에서 일치 항목 없음·미확인 모두) 표시한다. 전체 오류 카드(API 오류·접근 제한·출처 이용 불가)에는 오류 상태를 그대로 두고 ‘식약처에서 추가 확인’ 작은 텍스트 링크만 둔다.

**파일 일괄 조회 결과**

결과 상단에는 선택 국가/시장, 문서에 명시된 국가, 제품 유형·사용 조건, 실제 조회 범위, 서비스 조회 시각을 표시한다. 입력하지 않은 조건은 ‘미입력’으로 표시한다.

**요약 수치**

- 조회 대상 성분 수: 사용자가 이번 조회에 포함한 성분 항목 수. 사용 제외·조회 미포함 항목은 제외하며 매칭 실패 항목은 포함한다.
- 규제 정보가 조회된 성분 수: 해당 시장의 규제 근거가 실제 반환된 대상 항목 수. 통신 성공만으로 계산하지 않는다.
- 추가 확인이 필요한 성분 수: 규제 데이터 미확인, 매칭 실패·후보 미확정, 입력 부족, API 오류, 기준 불충족, 근거·적용 범위 부족 중 하나라도 있는 대상 항목 수.
- 각 수치는 성분 항목별로 한 번 계산한다. 규제 정보가 있어도 추가 확인이 필요할 수 있어 두 수치는 서로 배타적이지 않다. 동일 성분의 서로 다른 함량·조건 행을 임의 합산·병합하지 않는다.

**성분별 결과 표** (파일 일괄 조회)

화면에는 성분명·조회 상태·규제 유형·검토 상태·상세 보기를 중심으로 간결하게 두고, 요청 함량·규제 조건 원문·출처·오류 사유 전문은 상세 Modal에서 보여준다. 아래 열의 정보는 표 또는 상세 중 한 곳에서 확인할 수 있어야 한다. **현재 구현 표 열**: 성분명(매칭명·문서 함량 참고값 포함) · 선택 시장 · 조회 상태 · 규제 유형 · 상세. 검토 상태 열은 기준 비교 미구현으로 두지 않았다. 상세 Modal 은 직접 검색과 같은 Modal 을 공유하며 규제 조건을 영문 위·한국어 아래로 표시한다.

| 열 | 표시 내용 |
|---|---|
| 성분명 | 요청 성분명과 확정된 매칭명, 필수/선택 구분. 미확정이면 그 사실 표시 |
| 요청 함량 | 수치·단위·함량 기준 또는 q.s./미기재. 원료 투입량과 활성 성분 함량 구분 |
| 조회된 규제 정보 | 실제 반환된 규제 내용과 조회 상태. 없는 정보를 허용으로 해석하지 않음 |
| 사용 조건·함량 제한 | 제공된 적용 조건·제한(예: `limit_condition` 원문) 및 비교 가능한 기준. 미제공 항목 명시 |
| 검토 상태 | 해당 기준 충족 / 해당 기준 불충족 / 판단 보류와 이유. 제품 전체 판정이 아님 |
| 출처 | 제공된 자료명·링크 및 확인 가능한 날짜. 미제공이면 미제공 표시 |

‘조회 상태’는 규제 정보 조회됨 / 규제 데이터 미확인(시장 항목 없음) / 규제 목록 미등재 / 판단 보류 / 성분 매칭 실패 / 성분 확인 필요 / 접근 제한 / API 오류 / 미조회로 구분한다. ‘규제 데이터 미확인’은 API가 정상 응답했으나 선택 시장의 항목이 없는 경우(`not_listed_in_country`), ‘규제 목록 미등재’는 API 소스에 제한·금지 항목 자체가 없다고 안내한 경우(`not_listed`)이며 둘 다 허용·안전을 뜻하지 않는다. ‘접근 제한’은 401·403·429 응답(인증·요금제·호출 한도), ‘API 오류’는 연결·시간 초과·서버·형식 오류다. 결과 상단 요약은 조회 대상 / 규제 정보 조회됨 / 규제 데이터 미확인(+보류) / 접근 제한 / API 오류 / 성분 확인 필요 여섯 수치로 표시하며 각 행은 한 분류에만 속한다. ‘검토 상태’는 파일 일괄 조회에서 이와 별개로 표시하며 입력 정보 부족도 구체적인 사유로 표시한다. 예를 들어 규제 정보 조회됨과 함량 미기재에 따른 판단 보류는 동시에 표시할 수 있다. 직접 검색에는 검토 상태가 없다.

함량 단위·기준, 제품 유형·사용 조건, 적용 근거가 충분하고 서로 비교 가능할 때만 해당 기준과 비교한다. 단순 수치 대소 비교로 결론 내리지 않는다. `limit_condition` 등 규제 조건 원문은 원문 그대로 보존·표시하고, 원문에서 수치·조건을 해석해 비교할 때는 해석 근거를 함께 표시한다. 기준 충족 표시에는 비교한 조건과 근거를 명시한다. 근거가 부족하거나 출처를 확인할 수 없는 경우 판단 보류한다.

행의 상세보기는 공통 Modal로 제공한다. 원문/수정 입력, 매칭 정보, 조회된 세부 규제, 비교 근거·누락 정보(파일 조회), 실제 조회 범위 및 날짜를 표시한다. 규제 자료 갱신일, 서비스 조회 시각, 자체 검증일은 각각 다른 라벨로 표시하며 ‘확인일’ 하나로 합치지 않는다. 자체 검증을 하지 않았으면 ‘미실시’, 제공되지 않은 출처·갱신일은 ‘미제공’으로 표시한다.

성분 데이터가 전혀 없으면 Empty State를 제공한다. 성분별 실패·부족 사유가 있는 경우 이를 숨기지 않는다. 전부 규제 데이터 미확인일 때는 빈 결과 안내와 확인 필요 목록을 제공하며 ‘허용’·‘안전’으로 표시하지 않는다.

**식약처 공식 조회 연결 (2026-09-25)**: 결과 표 아래 순서는 ① 조회 상태 범례(메타) → ② 버튼 행(행별 상세는 표 안 ‘상세’ 버튼이 담당하므로 ‘식약처에서 사용제한 원료 확인’ 공통 보조 버튼만 **한 번**) → ③ 사전검토 안내와 작은 도움말(직접 검색 카드와 같은 문구·구성, 별도 패널 없음). 행마다 긴 안내를 반복하지 않는다. ‘규제 정보 조회됨’이 아닌 행(미확인·미등재·성분 연결 확인 필요·판단 보류·성분 확인 필요·매칭 실패·접근 제한·API 오류·미조회)의 조회 상태 셀과 전부 미확인일 때의 확인 필요 목록 항목에는 ‘식약처에서 추가 확인’ 작은 텍스트 링크를 붙인다. 기존 상태 배지·사유 문구는 그대로 두며 API 오류를 ‘규제 없음’·‘미등재’로 바꾸지 않는다. 상세 Modal 은 공통 안내를 반복하지 않고 ‘출처 · 날짜’ 아래에 같은 보조 버튼 하나와 작은 도움말만 둔다(기존 공공데이터포털 안내 링크 `data.go.kr` 은 다른 주소이므로 유지).

## 9. API / 외부 데이터

- 규제 정보 출처는 두 가지이며 화면에서 선택한다(직접 검색·파일 탭 각각 ‘규제 정보 출처’, **기본값 식약처 수집 DB**). (1) 식약처 ‘화장품 사용제한 원료정보’ 수집 DB(`instance/regulatory/mfds_use_restriction.sqlite`, 완료된 수집 실행만 사용, 읽기 전용) (2) 기존 K뷰티 API(RapidAPI). **선택한 출처만 조회하고 두 출처를 섞지 않으며, 식약처 조회가 실패해도 기존 API 로 자동 전환하지 않는다.** 두 출처의 우열은 확인되지 않았다. 성분명 검색·자동완성·성분 매칭은 계속 기존 API 로 하며, 사용제한 원료 DB 로 검색을 대체하지 않는다(일반 성분이 검색에서 사라지지 않게). API가 파일을 직접 읽는다고 가정하지 않는다.
- **식약처 DB 성분 연결**: 기존 API 성분 코드는 식별자로 쓰지 않는다. 확정 성분의 한글명·영문명·CAS 로 `INGR_STD_NAME`·`INGR_ENG_NAME`(대소문자·앞뒤 공백·연속 공백만 정규화, 숫자·기호 유지)·`CAS_NO`(토큰 단위) 정확 일치를 찾는다. 이름 일치 식별자(표준명+영문명 조합)가 정확히 하나면 확정, 둘 이상이거나 CAS 만 일치하거나 CAS 가 충돌하면 ‘성분 연결 확인 필요’(후보만 표시, 자동 확정 없음). 같은 성분·시장의 조건별 레코드는 모두 보여준다. 이름을 포함만 하는 항목(염류·유도체·성분군·이명·고시원료명)은 ‘관련 항목·적용 여부 확인 필요’로 확정 규제와 분리해 표시하며, 개별 이름으로 못 찾았다고 성분군 규정이 없다고 판단하지 않는다.
- **시장 매핑(식약처 DB)**: KR→한국, EU→EU, US→미국, CN→중국, JP→일본, ASEAN→아세안 (명시적 매핑, `regulatory_mfds_lookup.MARKET_TO_COUNTRY`). 원본 ‘유럽’(54건)은 근거가 없어 EU 에 합치지 않았으며 **이번 EU 조회 범위는 원본 ‘EU’ 항목**이다. 대만·캐나다·브라질·아르헨티나는 이번 단계에서 연결하지 않았다. 기존 API 출처는 기존 지원 범위(KR·EU·CN·US·JP·ASEAN)를 그대로 따른다.
- **식약처 결과 표시**: `REGULATE_TYPE`(금지/한도/한도/금지)과 `LIMIT_COND` 원문을 보존한다. `LIMIT_COND` 가 null 인 ‘금지’는 금지 항목으로 표시하고 ‘제한 없음’으로 해석하지 않는다. ‘한도’인데 제한사항이 비어 있으면 ‘상세 제한사항 미제공’. 단서조항은 `PROVIS_ATRCL`. 원문이 영문·한국어로 구분되면 기존 규칙대로 영문 위·한국어 아래, 아니면 원문 그대로(번역·생성 없음, 텍스트 노드로만 렌더링). 각 결과에 조회 출처와 DB 에 기록된 수집 시각을 표시하며 이는 원천 갱신일·법령 개정일이 아니다. 출처 링크는 공공데이터 안내 페이지(개별 법령 원문 아님)이며 응답에 없는 법령 URL·개정일은 만들지 않는다.
- **식약처 출처 상태**: 규제 항목 조회 성공(found) / 해당 출처에서 일치 항목 없음(not_listed, ‘출처에서 일치 항목 없음’ — 허용·안전·규제 없음 아님) / 성분 연결 확인 필요(link_required) / DB 미설치(db_missing 503) / 수집 미완료(db_incomplete 503) / DB 읽기 오류(db_error 503). DB 문제는 ‘출처 이용 불가’로 표시하고 미등재로 표시하지 않는다. 기존 API 출처의 접근 제한·호출 한도·오류 표시는 기존 규칙 그대로.
- 자동완성용 성분명 후보 검색과 국가별 규제 조회를 분리한다.
- 한글명·동의어 데이터가 부족하거나 부분·영문 검색을 지원하지 않으면 검증된 성분명 검색용 매핑 데이터로 보완하도록 설계한다. 한글·영문 검색 및 자동완성은 확정 목표이며, 보완 데이터의 출처·이용 조건·검증·갱신 방식은 구현 시 확정한다. 매핑 데이터를 `src/02_regulatory/` 안에 둘 경우 공개 가능한 자료만 포함한다.
- 파일 정보 추출 도구와 규제 데이터 조회는 별도 단계·의존성으로 설계한다. AI를 사용하더라도 문서 정보 추출에 활용하며 규제 근거가 없는 판정을 생성하지 않는다.
- 규제 정보 자체 DB는 확정 범위가 아니다. 미국 등 부족한 시장 정보의 보완 필요성, 구축 여부, 데이터 출처·검증·갱신 담당 및 범위는 API 확인 후 결정한다. 이는 성분명 검색을 위한 매핑 데이터 보완과 별개이며 성분명 매핑을 규제 근거로 사용하지 않는다.

## 10. 데이터 처리

**추출·정규화 규칙**

- 직접 검색은 입력 앞뒤 공백을 제거하고 영문 대소문자를 무시해 매칭한다. 한글명·영문 INCI명·검증된 동의어를 동일 성분 식별에 연결하되 원문 입력·표시명과 검색용 정규화 값을 구분한다.
- 매핑 데이터의 출처·검증 근거를 관리하며 AI 번역만으로 동일 성분을 확정하지 않는다. 이름이 비슷하거나 여러 성분에 연결되면 사용자 확인을 받는다. 후보 목록에 표시되었다는 사실은 규제 정보가 존재하거나 기준을 충족한다는 의미가 아니다.
- 요청 성분과 사용 제외 성분을 분리한다. 바이어의 제외 요청을 법적 금지로 표시하지 않는다.
- 필수 성분과 선택 성분을 구분하며 불명확한 경우 확인을 받는다. 사용 제외 성분을 처방 구성 성분 수에 포함하지 않는다.
- 원료 투입량과 활성 성분 함량을 구분한다. 농도·순도·환산 근거가 없으면 활성 함량으로 임의 환산하지 않는다.
- 단위와 함량 기준을 원문대로 유지한다. 비교를 위한 환산은 근거가 충분하고 기준이 일치하는 경우에만 수행하며 원문과 환산 근거를 함께 표시한다.
- q.s., 함량 미기재, 향료 상세 조성 미제공은 정보 부족이다. 이를 0 또는 제한 없음으로 해석하지 않으며 향료 세부 성분을 만들어내지 않는다.
- 문서에 없는 성분·함량·조건은 생성하지 않는다. 부분 개발요청서의 합계를 100%로 맞추거나 완성 처방으로 취급하지 않는다.
- 원문값, 추출값, 사용자 수정값과 매칭값을 구분한다. 후보가 모호하면 사용자가 확인하기 전 확정하지 않는다.
- 파일 추출값과 실제 규제 근거를 구분한다. 문서 자체에 기재된 ‘허용’ 등 표현을 공식 규제 조회 결과로 사용하지 않는다.

**보관·보안·운영 요구사항**

- 시장을 바꿔 재조회할 수 있도록 현재 작업의 확인·수정된 추출 정보를 유지한다. 영구 보관을 기본 전제로 하지 않는다.
- 업로드 원본과 임시 처리 파일은 `src/` 등 공개 자산 경로에 두지 않고 다른 사용자 작업과 분리한다. 확장자만으로 신뢰하지 않고 실제 형식·파싱 가능 여부를 검증한다.
- 처리가 끝나거나 실패한 임시 파일을 정리하는 삭제 절차를 마련한다. 원본 보관 기간, 추출값 유지 기간, 만료·작업 종료 시점, 실패 시 삭제 재시도 방식은 구현 시 확정한다. 미확정 상태에서 ‘즉시 삭제’ 등으로 안내하지 않는다.
- 외부 AI/OCR 서비스 사용 여부를 확정하고, 사용 시 전송 대상·목적·보관 및 삭제 정책·사용자 안내와 동의 필요 여부를 구현 전에 결정한다. 전송 전에 확정된 방침을 안내하며 미확정 상태에서 외부 미전송을 보장하지 않는다.
- API Key·요청 헤더 값은 코드, 문서, `test_data/`, 브라우저 응답, 로그에 남기지 않는다. 로그에는 원문 전체·민감한 처방 정보도 불필요하게 남기지 않는다. 구체적인 로그 저장 위치·접근 통제·보관 정책은 구현 시 확정한다.
- 자료 갱신일은 제공원 메타데이터, 서비스 조회 시각은 실제 호출 시각, 자체 검증일은 실제 별도 검증 기록으로 관리한다. 한 날짜를 다른 의미로 복사하거나 누락 날짜를 생성하지 않는다. 식약처 DB 의 ‘수집 시각’은 DB `runs.finished_at` 이며 별도 라벨로만 표시한다.
- **상세 Modal 정보 배치 정리 (2026-09-26)**: 직접 검색·파일 일괄 조회가 공유하는 성분 상세 Modal 을 공통 디자인 기준으로 재배치했다(표시 방식만 변경, API 호출·매칭·규제 판정 로직 변경 없음). 기본 펼침: ① 한국어 성분명·영문명 / 선택 시장 · 조회 상태 배지(조회됨은 중립 배지, ‘사용 허용·적합 판정이 아니에요’ 문구 동반) · 규제 구분 / 문서 함량(참고, 파일 조회만) / 미조회·오류 사유 → ② ‘주요 규제 조건’: 언어별 큰 덩어리 대신 항목별(① 적용 제품·부위 ② 최대 농도 ③ 사용 조건·주의 문구, 분류 불확실은 ‘제한사항’)로 묶고 항목 안에서 영문 원문 위·한국어 제공 내용 아래. 기존 `parseConditionText` 구조화 로직 재사용(블록 경계에 줄바꿈 없이 이어지는 ‘ * 【태그】’ 를 추가 인식해 머리글이 앞 값에 섞이지 않게 함), 번역·요약 없음, (a)(b) 대응·수치·단위·RE·경고 문구 보존, ‘【Restrictions】/【제한】’ 머리글과 항목 제목과 겹치는 라벨만 생략 → ③ 관련 항목은 ‘관련 항목 N건 · 적용 여부 확인 필요’ 건수는 항상, 목록은 접힘. 식약처 성분 연결 후보(link_required)는 접지 않고 표시. 기본 접힘(접근 가능한 details/summary, 화살표 + ‘펼치기/접기’ 글자): ‘입력·매칭 근거’(검색어·시장·매칭 성분 code·매칭 방식·성분 연결 근거·성분 레코드 updated_at(규제 자료 갱신일 아님 설명 유지)·원문 위치 — 결과 표 열로는 두지 않음) / ‘전체 원문·고시 정보’(고시 성분명·규제 조건 전체 원문·단서 조항·API 안내 문구·응답 상태값·실제 조회 범위 — 등재 시장 목록은 ‘K뷰티 API 에 등재된 시장’ / ‘식약처 DB 에 레코드가 있는 국가’로 출처를 구분) / ‘출처·날짜 상세’(출처 설명은 공공데이터 안내 URL 을 링크 하나로만, 개별 법령 원문 링크 아님 명시 · 제공원 고지 · 갱신 방식 · 수집 시각은 확보 시각과 같은 수집 완료 기록이면 표시하지 않고 다를 때만 별도 · 수집 실행 정보(식약처) · 원천 자료 갱신일·법령 개정·적용일 미제공 · 서비스 조회 시각 · 자체 검증일 미실시). 하단에는 규제 조회 출처·데이터 확보 시각·‘확보 시각은 법령 개정일이나 최신성 보장을 뜻하지 않아요’ 를 항상 짧게 두고, 사전검토 안내 한 문장과 도움말, 하단 버튼은 식약처 공식 조회(`.btn-soft`, 새 탭, `noopener noreferrer`, 외부 링크 아이콘)와 닫기. 상세 안에 상세를 다시 여는 버튼은 없다. 정의 목록은 데스크톱 2열(짧은 식별정보)·1열(긴 원문), 640px 이하 1열, 긴 화학명·원문은 `overflow-wrap`·`pre-wrap` 으로 가로 넘침 없이 줄바꿈. 접근성: 열 때 닫기 버튼으로 포커스 이동·스크롤 맨 위·펼침 상태 초기화(다른 성분을 열어도 이전 상태가 남지 않음), Tab 순환, Esc 닫기(공통), 닫은 뒤 연 버튼으로 포커스 복귀(`regulatory.js` 상세 Modal 접근성 보완). 직접 검색 카드 본문의 규제 조건도 같은 렌더러를 쓰므로 같은 항목별 배치가 적용된다. 검증(2026-09-26, headless Chrome + 캐시 응답 로컬 서버, 외부 호출 0회): 직접 검색·일괄 조회 × 식약처·K뷰티 × 조회됨·미등재·미확인·성분 연결 확인 필요·API 오류 화면, 수정 전후 원문 동일(전체 원문 = 응답 `limit_condition`), 수치·단위·(a)(b)·경고 문구 보존, 포커스·Tab·Esc·복귀, 390px 폭 가로 넘침 없음 — 50개 항목 통과. **미검증**: 실제 화면 크기별 시각 확인과 스크린리더 읽기 순서는 담당자 브라우저 확인 필요.
- **식약처 공식 조회 링크 동작 (2026-09-25)**: 주소는 `https://nedrug.mfds.go.kr/pbp/CCBDF01` 하나이며 실제 `<a>` 로 `target="_blank"`·`rel="noopener noreferrer"` 를 적용해 새 탭에서 연다. 검색어 자동 전달 방식이 확인되지 않아 URL 에 쿼리 파라미터를 붙이지 않고, 버튼은 공식 조회 페이지로 이동할 뿐 해당 성분 상세 페이지로 바로 연결되는 것처럼 표현하지 않는다(도움말: 공식 페이지에서 성분명·영문명·CAS 번호로 직접 검색). 링크 이동은 JS 상태를 건드리지 않으므로 입력값·업로드 결과·선택한 시장·출처·상세 Modal 상태가 유지된다. 외부 링크 아이콘(`aria-hidden`)과 보조기기용 ‘(새 탭에서 열림)’ 문구(`regulatory-sr-only`)를 함께 둔다. 기존 API 호출·성분 검색·매칭·OCR·규제 판단 로직은 변경하지 않았다.
- **출처 선택 UI (2026-09-24)**: 직접 검색·파일 탭의 ‘규제 정보 출처’는 드롭다운이 아니라 radio 카드 2개(식약처 수집 DB / K뷰티 API (RapidAPI))의 단일 선택이다. 기본 선택은 식약처 수집 DB. 실제 `<input type="radio">`를 카드 모양 `<label>` 로 감싸 카드 전체 클릭·Tab·방향키·Space 선택이 되고, 선택 상태는 공통 강조색 테두리와 옅은 배경, 미선택은 중립 테두리·배경으로 표시한다(값은 design_system 변수만 사용). 내부 값(`mfds` / `api`)과 `source` 파라미터 전달 방식은 그대로이며, 값은 checked 인 radio 에서 읽고 change 는 fieldset 에서 한 번 받아 ‘이전 조건의 결과’ 안내·재조회 흐름을 유지한다. 결과 표시·화면 갱신은 선택값을 바꾸지 않는다. 두 출처 동시 조회·병합은 제공하지 않는다. 사용자용 명칭 ‘기존 API’는 ‘K뷰티 API (RapidAPI)’로 통일했다.
- **발표 시연 자료 (2026-09-25)**: `samples/` 바로 아래에 최종 3개만 둔다(같은 날 `samples/demo/` 하위 폴더를 없애고 이동) — 영어 염모제 개발요청서 PDF(KR·EU·CN·ASEAN), 한국어 두피샴푸 주요 검토 성분표 XLSX(한국·EU·중국·아세안), 영어 선 에센스 주요 검토 성분표 PNG(KR·EU·CN·JP·ASEAN). 성분은 실제 검색·매칭·6시장×2출처 규제 조회로 검증해 선정했고(추천 시장은 두 출처 각각 90% 이상), 파일별·시장별·출처별 성공 건수, 수동 처리(살리실릭애씨드 식약처 `link_required`), 미검증 항목은 `demo_verification.md` 에 기록했다. 회귀 테스트 픽스처(`sample_*`·`EU-SER-041_development_brief.pdf`)는 `tests/fixtures/` 로 이동해 유지하고, 추출 성공 여부만 확인하던 `sample_ingredients_kr.xlsx` 는 한국어 두피샴푸 XLSX 로 참조를 바꾼 뒤 삭제. 시장 표기는 조회 시연 추천이며 수출 적합성 인증이 아니다.
- **출처별 날짜·갱신 안내 (2026-09-23)**: 결과 카드·일괄 결과 상단·상세 Modal 에 ‘데이터 확보 시각 / 갱신 안내 / 원천 자료 갱신일 / 법령 개정·적용일’을 구분해 표시한다. 시간은 KST 로 통일한다(시간대 정보가 없는 값은 변환하지 않고 ‘시간대 미표기’). (1) K뷰티 API: 확보 시각 = 서버가 외부 API 응답을 받은 시각(`acquired_at` = `queried_at`)이며, 화면은 응답에 담긴 값을 그대로 쓰므로 이전 결과를 다시 볼 때도 현재 시각이 아니라 원래 확보 시각이 보인다. 갱신 안내는 ‘월 1회 (제공자 안내 기준)’ — 근거는 제공자 공개 저장소 README 의 “Update Frequency | Monthly”(2026-09-23 확인)이며, 마지막 갱신일·스냅샷 날짜는 문서·응답 어디에도 없어 ‘미제공’으로 두고 역산하지 않는다. (2) 식약처 DB: 확보 시각 = 조회에 쓰는 완료된 수집 실행의 `runs.finished_at`(수집 완료 시각). 파일 수정 시각·현재 시각을 쓰지 않으며, 재수집이 실패하면 이전 완료 실행이 그대로 쓰여 이전 수집 시각이 유지된다. 값이 없으면 ‘수집 시각 미기록’. 자동 갱신이 없으므로 갱신 안내는 ‘수동 재수집 (자동 갱신 없음)’. (3) 두 출처 모두 원천 자료 갱신일·법령 개정·적용일은 ‘미제공’이며, 공공데이터포털 소개 페이지의 수정일을 갱신일로 쓰지 않는다. (4) 안내 문구 ‘데이터 확보·수집 시각은 법령 개정일이나 최신성 보장을 의미하지 않습니다.’를 함께 표시하고, 시각만으로 출처 간 최신성을 판정하지 않는다. 일괄 결과는 상단에 공통 정보(출처·확보 시각 범위·갱신 안내)를 한 번 표시하고, 행마다 확보 시각이 다르면 범위로 보여주며 개별 시각은 상세에서 확인한다.

## 11. 예외 처리

| 상황 | 표시 및 복구 동작 |
|---|---|
| 검색어·시장 미입력 | 해당 폼에 오류 안내. 입력 전 조회 실행 방지 |
| 자동완성 입력 2글자 미만·한글 조합 중 | 후보 요청하지 않음. 2글자 미만에서는 목록 닫기, 조합 완료 후 약 300ms 대기하여 조건 재확인. 서버 Route는 2글자 미만을 검증 오류(400)로 응답 |
| 자동완성 후보 없음 | ‘일치하는 성분이 없습니다’ 표시. 규제 데이터 미확인과 구분하고 입력 수정 안내 |
| 성분명 후보 검색 실패 | 후보 검색 실패와 재시도 안내. 후보 없음으로 표시하지 않고 입력 유지. 규제 조회 API 오류와 별도로 표시 |
| 후보 미선택 상태에서 검색 | 현재 입력으로 매칭 시도. 여러 후보이면 사용자 선택 요청, 매칭 실패이면 수정 안내. 임의의 첫 후보로 규제 조회 금지 |
| 후보 선택 후 검색어 수정 | 기존 성분 선택 해제, 수정된 입력으로 후보 재검색. 이전 선택 성분으로 규제 조회 금지 |
| 이전 후보 요청의 늦은 응답 | 현재 목록을 덮어쓰지 않음. 이미 닫힌 목록을 재개방하지 않음 |
| 흐름 점검 보완 (2026-09-23) | 직접 검색과 파일 일괄 조회는 결과 영역·상세 Modal 을 공유하므로 (1) 일괄 결과가 보일 때 직접 검색의 ‘이전 조건’ 안내를 끄고, (2) 직접 검색 카드의 ‘규제 원문·출처 보기’는 열기 직전에 마지막 직접 검색 결과로 Modal 을 다시 채운다. (3) 새 파일 추출을 시작하면 이전 파일의 성분 확인·규제 조회를 중단하고 플래그·버튼·일괄 결과를 정리하며, 추출이 실패하면 이전 확인 표(수정 내용 포함)를 되살린다. (4) 일괄 조회의 ‘이전 조건’ 판정 키는 조회 시작 시점 기준이라 조회 중에 행을 고치면 완료 후 안내가 뜬다. (5) 자동완성 목록이 다른 검색어의 것이면 검색 버튼은 후보를 다시 검색한다. (6) 성분 확인 처리 중 예외가 나도 버튼이 ‘확인 중’에 고정되지 않는다. (7) 직접 검색 오류 카드는 입력 확인·연결 실패·접근 제한·API 오류를 구분해 표시한다 |
| 지원하지 않는 문서 시장 | 원문 국가와 미지원 표시. 사용자 선택 없이 다른 시장 대체 금지 |
| 미지원 파일·제한 초과 | 업로드 오류와 허용 형식·확정된 제한 안내. 파일 교체 유도 (구현: 이미지·.xls·.csv 등은 415 `unsupported`, 10 MB·20쪽·20시트 초과는 400 `limit`. 화면은 업로드 전에도 같은 안내) |
| 손상·암호화 등 읽기 실패 | 읽을 수 없는 이유와 재업로드·직접 입력 안내. 규제 데이터 미확인과 구분 (구현: 422 `unreadable`) |
| OCR 오인식·불명확한 표 | 해당 항목을 확인 필요로 표시. 확정값 생성 금지, 수정 또는 재업로드 제공 (구현: OCR 로 읽은 모든 행을 ‘확인 필요(OCR)’로 표시. 글자 인식 실패는 ‘이미지에서 글자를 인식하지 못했어요’, 글자는 읽었으나 제목을 못 찾으면 ‘성분 표 구조를 찾지 못했어요’ + 인식된 줄 예시(`ocr.outcome` = no_text / no_header), 시간 초과·처리 실패는 422 `ocr_timeout`/`ocr_failed`, 엔진 미설치는 503 `ocr_unavailable` + 설치 안내) |
| 일부 페이지·시트 추출 실패 | 성공 범위와 미처리 범위를 명시하고 확인·수정 가능. 문서 전체 추출 완료로 표시 금지 |
| 성분 미검출·빈 시트 | 추출 Empty State와 시트 재선택·재업로드·직접 입력 안내 (구현: `status = empty`, 표는 비어 있고 ‘행 추가’로 직접 입력 가능) |
| 성분 매칭 실패 | 실패 상태 및 성분명 수정 안내. 규제 데이터 미확인과 구분 (구현: 확인 표 ‘성분 확인 필요’, 결과 표 ‘성분 매칭 실패’. 조회하지 않음) |
| 여러 매칭 후보 | 후보 확인 전 성분 확인 필요 상태. 해당 항목을 임의 확정하지 않고 나머지 결과는 제공 (구현: 행의 후보 목록에서 선택. 미확정 행은 결과 표에 ‘성분 확인 필요’로 남고 조회하지 않음) |
| 함량·기준·조건 부족 (파일 조회) | 구체적인 누락 항목 표시. 규제 정보 조회는 가능하되 기준 비교는 판단 보류. 직접 검색에는 해당 없음 |
| API 정상 응답에 규제 데이터 없음(예: `data=[]`, `not_listed_in_country`) | ‘규제 데이터 미확인’과 추가 확인 필요 표시. 허용·안전 판단 금지 |
| 확인하지 않은 `result_status` 값·예상과 다른 응답 구조 | 임의 해석 금지. 판단 보류·추가 확인 필요로 표시 |
| API 인증·연결·시간 초과·호출 제한·응답 오류 | API 오류 표시, 민감정보 없는 사유와 재시도 안내. 규제 데이터 미확인으로 변환 금지 |
| 서버에 `RAPIDAPI_KEY`·`RAPIDAPI_HOST` 미설정 | 외부 호출 없이 설정 오류로 처리. 화면에는 Key 값·변수 내용 없이 관리자 확인 필요 안내 |
| 일부 성분 조회 실패 | 성공 결과 유지, 실패 항목과 건수 표시 및 해당 항목 재시도 제공 |
| 전체 조회 실패 | 공통 Error State와 재시도. 확인한 입력은 유지 |
| 재조회 또는 입력 변경 | 이전 조건의 결과임을 명시하고 재조회 요구. 오래된 응답이 새 조건 결과를 덮어쓰지 않음 |

처리 중 ‘업로드 중’, ‘시트 확인 중’, ‘텍스트·표 추출 중’, ‘문자 인식 중’, ‘규제 조회 중’ 등 실제 단계에 맞는 상태를 표시한다. 측정할 수 없는 진행률은 만들지 않는다. 실행 버튼은 로딩·disabled로 중복 실행을 막고 서버에서도 중복 처리 방식을 마련한다. 종료·오류 후에는 복구 가능한 동작을 다시 활성화한다.

- **상세 Modal 위치 (2026-09-23, PM 공유 사항)**: 공통 `main.container` 에 `container-type: inline-size` 와 진입 애니메이션(`transform`)이 있어 그 안의 `position: fixed` Modal 은 뷰포트가 아니라 컨테이너 기준으로 배치된다(긴 페이지에서 배경만 보이고 창은 화면 밖). 담당 JS 가 페이지 로드 시 `#regulatory-detail-modal` 을 `body` 바로 아래로 옮겨 해결했다. 공통 `common.js` 는 id 로 찾으므로 동작은 같다. 같은 구조의 다른 페이지 Modal 도 영향을 받을 수 있어 PM 에게 공유한다.
- 공통 UI 문서의 Table 설명은 Header 14px·배경 없음이나 실제 CSS는 `--font-size-caption`·`--color-surface-muted`를 사용한다. 페이지 CSS로 덮어쓰지 않고 PM이 규격과 구현의 정합성을 확정해야 한다.
- 공통 CSS의 Shape 주석은 Card 그림자 없음으로 되어 있으나 디자인 문서와 실제 `.card`는 `--shadow-card`를 사용한다. 주석 정합성은 PM 확인 사항이다.
- 전부 규제 데이터 미확인일 때 공통 ‘Table 대신 Empty State’ 규칙과 성분별 실패 사유 표시를 함께 충족하는 구체적 배치는 PM과 확인한다. 빈 결과 안내 아래 확인 필요 목록을 제공하는 요구사항은 유지한다.
- 추출값 편집 표·시트 선택·단계 표시 등은 기존 Form·Table·Alert 조합을 우선한다. 별도의 공통 컴포넌트가 필요하면 규격을 새로 정의하지 말고 PM과 협의한다.

## 13. Flask / app.py 연동

- 기존 프로젝트 구조에 맞춰 구현한다. 긴 처리 로직(외부 API 호출, 파일 추출, 매칭·비교)은 `src/02_regulatory/` 내부 Python 모듈에 두고, `app.py`에는 Route와 필요한 연결 코드(import 등)만 둔다. Blueprint나 별도 실행 파일은 필수 구조가 아니다.
- `app.py`는 하단 `[B] 국가별 인허가 규제` 영역에 필요한 Backend Route와 연결 코드를 추가할 수 있다. 기존 Route와 다른 담당자 영역은 변경하지 않는다.
- 새 API URL은 `/api/regulatory/` 접두사, 새 Flask 함수명(endpoint)은 `regulatory_` 접두사를 사용한다. 기존 페이지 URL `/regulatory`와 endpoint `regulatory`는 유지한다.
- 서버가 파일 추출 도구 및 규제 API를 호출한다. 브라우저가 비밀 Key를 보유하거나 외부 규제 API를 직접 호출하지 않게 한다.
- 페이지 JS는 IIFE 또는 `DOMContentLoaded` 안에 작성하여 전역 변수 충돌을 방지한다. 공통 탭·Modal 동작은 재구현하지 않는다.
- 요청 검증·오류 구분·부분 성공 응답 계약과 처리 상태 전달 방식은 구현 시 확정하여 `api_reference.md`에 기록한다.

**환경변수**

- 서버는 프로젝트 최상위 `.env`의 `RAPIDAPI_KEY`, `RAPIDAPI_HOST`를 사용한다. `app.py`의 기존 `load_dotenv()`로 로드된 값을 `os.getenv()`로 읽는다.

**OCR 설치·실행 (2026-09-23)**

- 서버는 `regulatory_ocr.py` 가 환경변수 `TESSERACT_CMD`(실행 파일) → PATH → 기본 설치 경로 순으로 Tesseract 를 찾고, `TESSDATA_PREFIX`(kor·eng traineddata 폴더)를 쓴다. 두 변수 이름은 `.env.example` 에 추가했으며 값은 로컬 `.env` 에만 둔다.
- **Windows 개발 환경**: (1) `winget install UB-Mannheim.TesseractOCR` (기본 설치 경로 `C:\Program Files\Tesseract-OCR`, eng 포함) (2) 한글 데이터 `kor.traineddata` 를 https://github.com/tesseract-ocr/tessdata 에서 받아 사용자 폴더(예: `%LOCALAPPDATA%\COSMOA\tessdata`)에 두고 같은 폴더에 `eng.traineddata`·`osd.traineddata` 를 복사 (Program Files 는 관리자 권한 필요) (3) `.env` 에 `TESSERACT_CMD`, `TESSDATA_PREFIX` 지정 (4) `pip install -r requirements.txt` (pytesseract·Pillow·pypdfium2).
- **배포 서버(Linux)**: `apt install tesseract-ocr tesseract-ocr-kor tesseract-ocr-eng` 후 `pip install -r requirements.txt`. 기본 경로에 설치되면 환경변수 없이 동작한다. OCR 은 CPU 를 쓰므로 워커 수·요청 시간 제한(최소 90초 이상)을 서버 설정에 반영한다.
- 준비 여부는 `regulatory_ocr.availability()` 가 확인하며 부족한 항목(실행 파일·언어 데이터·pip 패키지)을 오류 메시지에 그대로 적는다. OCR 이 없어도 텍스트 PDF·Excel 은 동작한다.
- 렌더링·축소 이미지는 메모리에서만 다루고, 인식 텍스트·파일명은 로그에 남기지 않는다.

**식약처 ‘화장품 사용제한 원료정보’ 수집 스크립트 (2026-09-23, 조사 단계)**

- 목적: 기존 RapidAPI 교체 전에 식약처 공공데이터의 국가별 범위·활용 가능성을 확인한다. 기존 화면·조회 연결은 바꾸지 않았고, 서버 시작이나 사용자 검색 때 실행되지 않는다.
- 출처: 공식 안내 https://www.data.go.kr/data/15111772/openapi.do, 호출 `GET https://apis.data.go.kr/1471000/CsmtcsUseRstrcInfoService/getCsmtcsUseRstrcInfoService` (serviceKey · pageNo · numOfRows · type=json). 응답 `body.items` 는 배열, 단서조항 필드는 `PROVIS_ATRCL`. 공식 페이지의 요청 변수 표(numOfRows 최대)·호출 제한은 스크립트 렌더라 확인하지 못했고(‘개발계정 트래픽 10,000’만 확인) 페이지 크기·간격은 환경변수로 조정한다.
- 설치: 추가 패키지 없음(requests·python-dotenv·sqlite3). `.env` 의 `MFDS_API_KEY` 에 Decoding 인증키 (이름은 `.env.example` 에 있음). 키·키 포함 URL 은 저장·로그·보고에 남기지 않는다. 기존 RapidAPI 변수는 그대로 둔다.
- 저장: `instance/regulatory/mfds_use_restriction.sqlite` (Git 제외 `instance/`, `/assets` 공개 경로 아님, 기존 서비스 DB `instance/cosmoa.db` 와 별개). 테이블 `runs`(실행 조건·시각·상태·건수·호출 수) / `pages`(쪽별 요청·응답 건수·totalCount·resultCode·HTTP·내용 해시) / `records`(원본 9개 필드 그대로 + raw_json + run·page·row). 페이지 하나가 트랜잭션이며 이미 저장된 쪽은 다시 저장하지 않는다.
- 실행 (프로젝트 루트, `conda activate tdenv`): `python src/02_regulatory/mfds_use_restriction.py probe`(5건 1회 호출로 연결·구조 확인) → `... collect`(순차 수집, 진행 중 실행이 있으면 자동 재개; `--max-pages N`, `--new-run`, `--allow-count-change`) → `... status` → `... analyze`(API 호출 없음) → `... find Retinol 레티놀`(API 호출 없음). 환경변수 `MFDS_PAGE_SIZE`(기본 100) `MFDS_REQUEST_INTERVAL`(초, 기본 0.3) `MFDS_TIMEOUT` `MFDS_MAX_RETRIES` `MFDS_DB_PATH`.
- 안전장치: 첫 쪽에서 요청 페이지 크기가 실제 적용됐는지 확인(아니면 중단), 본 수집 중 페이지 크기 고정, 재개 시 페이지 크기·totalCount 변화 확인, 인증(401/403·resultCode 20/30~33)·한도(429·22) 오류는 재시도 없이 중단, 일시 오류는 제한 재시도, `resultCode≠00`·XML 오류·예상 밖 구조는 빈 데이터로 취급하지 않고 중단, 반복 페이지·조기 빈 페이지 감지, 완료 건수와 totalCount 대조. 미완료 실행은 `status` 로 구분되고 이전 완료 데이터는 유지된다.
- 해석 원칙: 같은 성분의 국가별·조건별 레코드를 합치거나 지우지 않는다. `LIMIT_COND` 가 null 인 ‘금지’ 를 ‘제한 없음’으로 보지 않는다. 미조회 성분을 허용·안전·규제 없음으로 판단하지 않는다. 수집 시각은 원천 갱신일·법령 개정일이 아니다. 복수 물질·CAS·이명은 원문 그대로 두고 분석 집계에서만 정규식으로 CAS 토큰을 센다.
- 검증: `python -m unittest discover -s src/02_regulatory/tests -p "test_mfds*.py"` (수집 모의 응답 16개 + 조회 모듈·Route 테스트).

**식약처 DB 서비스 연결·팀원 PC·배포 서버 준비 (2026-09-23)**

- 서비스는 `regulatory_mfds_lookup.py` 가 `MFDS_DB_PATH`(선택) 또는 `instance/regulatory/mfds_use_restriction.sqlite` 를 **읽기 전용(mode=ro)** 으로 열고, `runs.status` 가 completed/completed_with_warnings 인 최신 실행만 쓴다. DB 가 없으면 만들지 않고 503 `db_missing`, 완료 실행이 없으면 503 `db_incomplete`, 열지 못하면 503 `db_error` 를 돌려준다. 서버 시작·사용자 조회 때 수집은 실행되지 않는다.
- **팀원 PC 준비 (두 방법 중 하나)**: (A) 재수집 — `.env` 에 `MFDS_API_KEY` 를 넣고 `conda activate tdenv` 후 `python src/02_regulatory/mfds_use_restriction.py collect` (약 313회 호출, 3~4분). (B) 복사 — 이미 완료된 `instance/regulatory/mfds_use_restriction.sqlite` 파일을 같은 경로에 두면 된다(DB 에는 인증키·개인정보가 없고 수집 실행 정보·원본 레코드만 있다). 복사 전 원본 PC 에서 `... status` 로 `completed` 인지 확인하고, 복사 중 수집이 돌고 있지 않게 한다. 어느 방법이든 `.env` 는 각자 보관하며 DB 파일은 Git 에 넣지 않는다(`instance/` 제외).
- **배포 서버 준비**: 서버에 `instance/regulatory/` 폴더를 만들고 완료된 DB 파일을 업로드(예: scp)하거나 서버에서 (A) 를 1회 실행한다. 웹 프로세스는 읽기만 하므로 재수집은 별도 셸에서 `collect --new-run` 으로 새 실행을 만들고, 완료되면 다음 조회부터 최신 완료 실행이 자동으로 쓰인다(미완료 실행은 사용되지 않는다). DB 는 공개 정적 경로(`src/`, `/assets`)로 옮기지 않는다. 실제 배포·업로드는 이번 작업에서 하지 않았다.
- 재수집 vs 복사: 재수집은 최신 원천 데이터를 받지만 API 호출과 시간이 들고 totalCount 가 바뀔 수 있다. 복사는 수집 시각이 원본 PC 기준으로 고정된다(화면의 ‘수집 시각’ 이 그 시각이다).

**업로드·임시 파일 위치**

- `/assets/` Route가 `src/` 안의 허용 확장자 파일을 공개하므로, 업로드 원본·임시 파일은 `src/` 밖의 비공개 경로에서 처리한다. **구현(2026-09-23)**: OS 임시 디렉터리(`tempfile.mkstemp`, 접두사 `cosmoa-reg-`)에 저장해 요청 안에서 처리하고, 성공·실패와 관계없이 `finally`에서 삭제한다. 서버에 파일·추출값을 보관하지 않으며(시트 선택은 재전송 방식), 추출값은 브라우저 메모리에만 있다가 페이지를 떠나면 사라진다. 로그에 문서 내용·파일명·Key 를 남기지 않는다. 프로젝트 내 폴더는 만들지 않았다.

- **담당 폴더**: `src/02_regulatory/` 안의 HTML·CSS·JS·MD, Python 모듈, `api_reference.md`, `test_data/`, `samples/`, 테스트 코드.

## 16. 완료 조건

아래는 **기능 구현 완료를 검증하는 체크리스트**이다. 실제로 구현하고 테스트한 항목만 체크하며 현재는 모두 미완료이다. 연동은 실제 API 호출로 검증하고, 오류·누락 사례는 `test_data/`의 재현 가능한 응답 예시도 활용한다.

- [ ] `/regulatory`에서 공통 레이아웃과 두 탭이 표시되고 각 탭에서 시장을 선택할 수 있다.
- [ ] 시장 선택과 규제 조회 연동이 실제 API 호출 결과와 일치하며, 한글·영문 입력은 API 또는 검증된 매핑 데이터를 통해 조회되어 제공 범위의 규제 정보·조건·제한·출처·날짜가 표시된다.

- [ ] 레티놀(EU)처럼 규제 데이터가 반환된 사례에서 `limit_condition` 원문이 표시되고, 레티놀(US)처럼 `data=[]`·`not_listed_in_country`인 사례는 ‘규제 데이터 미확인’으로 표시된다.
